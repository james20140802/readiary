# 로그인 이후 UI 검토 — 2026-09-09

사용자가 승인한 브라우저 저장 로그인으로 Readiary에 접속했다. Frontend Design Premium, Build Web Apps, Impeccable 기준으로 독립 디자인 평가와 DOM·상태 검증을 합쳤다. 이전 보고서의 로그인 이후 코드 검토를 실제 화면 증거로 보완한다.

## 검토 범위

- 프로덕션의 홈, 책장, 펼친 책, 책 상세, 기록 작성, 프로필 앞·뒷표지·펼침·월별 회고, 소셜, 프로필 수정, 알림 설정을 확인했다.
- 데스크톱 다크 화면과 390×844 다크 화면을 확인했다. 모바일은 홈·책장·책 상세·기록 작성·프로필·알림 설정을 확인했다.
- 홈에 검토용 미저장 초안을 입력해 화면 이탈과 복귀를 시험했다. 빈 기록 제출은 클라이언트 유효성 검사까지만 확인했다. 기록 생성·수정·삭제, 좋아요·댓글, 사진 업로드, 공유, 푸시 전송·설정 변경은 하지 않았다.
- 라이트 실화면, iPhone 설치형 PWA, 소프트웨어 키보드, VoiceOver 실사용, 실제 저장·오류 네트워크·푸시 수신은 검증하지 않았다. DOM의 접근성 이름 확인을 스크린리더 실기기 검증으로 표현하지 않는다.
- 검토 근거 코드는 문서 변경 브랜치 `docs/project-agents-ui-review`다. 이번 후속 조사에서도 제품 코드를 변경하지 않았다.

## 판단

‘먹과 종이’는 실제 데이터에서도 유지된다. 특히 책 상세는 긴 문장과 생각을 읽기 좋은 원고 흐름으로 보여준다. 책장의 물성과 실용적인 상세 링크, 프로필의 넘김·닫기, 알림의 상태 설명은 보존할 가치가 있다.

우선할 개선은 **쓰던 내용을 잃지 않기, 회고에서 끝까지 읽기, 모든 사용자가 같은 행동에 접근하기**다. 새로운 시각 장식보다 현재 행동을 완결하는 쪽이 효과가 크다.

사진 제거 버튼에는 title로 이름이 있으므로 ‘이름이 없다’고 판단하지 않는다. 문제는 업로드 시작점이다. 프로필의 반복된 뒷면 DOM도 inert 처리가 있어, DOM 스냅샷에 나타난다는 이유만으로 모두 키보드에 노출된다고 판단하지 않았다.

## 화면별 좋은 점과 세부 보완

- **홈:** 입력창의 주도성이 명확하고, 모바일 컨트롤이 두 줄로 정돈된다. 초안 보존과 공개 대상 설명을 보완하면 첫 기록 행동이 더 안정적이다.
- **책장·상세:** 확인한 모바일 책장에 가로 잘림이 없었다. 펼친 책의 ‘책 상세’와 원고형 기록, 명시적인 ‘기록 남기기’가 좋다. 작은 반응 버튼은 이름과 터치 영역을 함께 개선한다.
- **작성:** 문장·생각·선택 쪽수·날짜가 자연스럽게 이어지고 공개 범위 설명이 있다. 빈 입력 오류는 보이지만 접근성 연결이 부족하다. 확인한 390px 화면에서 가로 overflow는 없었다.
- **프로필:** 책의 앞뒤와 월별 탐색은 동작한다. 기록을 소장하는 느낌은 좋지만, 월별 원문 연결이 필요하다. 사진 변경 시작점의 키보드 접근을 우선한다.
- **프로필 수정:** 텍스트 필드 label 연결은 올바르며 책·문장 변경 컨트롤은 이름과 44px 높이를 갖춘다. 사진 제거 22px, 비밀번호 변경 약 20px 높이는 터치 여유를 보완할 후보다.
- **소셜:** 엽서의 문장·출처·작성자 위계가 일관된다. 댓글 버튼 이름을 보완한다. 실제 반응 쓰기는 수행하지 않았다.
- **알림:** 받는 종류와 빈도, 기기 상태를 설명하며 로딩 중 제어를 막고 이후 활성화한다. 실제 화면은 ‘이 기기 알림 꺼짐 · 본인 계정 테스트 중, 자동 발송은 꺼져 있어요’를 표시했다. 전송 준비·활성화·수신 완료를 혼동하지 않는다.

이전 라이트 대비 발견(종이 위 ink-faint 2.51:1)은 그대로 남아 있으나 이번에는 라이트 실화면을 추가 확인하지 않았다. 그림자·파란 잉크·알약형 컨트롤은 기존 제품 맥락으로 판단하며 일반 템플릿 기준으로 제거하지 않는다.

잠정 설계 평가이며 이전 평가를 유지한다. 같은 문제의 실화면 확인이므로 개선된 점수로 올리지 않았다. 검토 범위가 넓어졌다는 사실과 품질 개선은 다르다.

이동 중 독자는 책 변경에서 초안을 잃고, 회고 독자는 잘린 문장의 원문을 다시 찾아야 하며, 키보드 사용자는 사진 변경의 시작점에 도달할 수 없다. 조용한 첫인상과 책장의 애착이 실제 행동의 막힘으로 꺾이지 않도록 하는 것이 핵심이다.

자동 검사는 제품 코드가 바뀌지 않아 이전 app/components 0건 결과를 재사용했다. 새 검사 통과로 보고하지 않는다. 실제 동작·접근성 이름·키보드 시작점은 자동 검사와 별도로 확인했다. 브라우저는 탭 단위 DOM/스크린샷을 사용했고, 읽기 전용 제약으로 시각 오버레이를 삽입하지 않았다.

후속 판단 질문: 책을 선택하는 일이 초안을 떠날 이유가 있는가? 회고를 본 독자가 어디서 원문을 끝까지 읽는가? 사진을 바꾸는 동일한 행동을 키보드로도 시작할 수 있는가?

AGENTS.md의 추가 품질·운영 규칙 다섯 가지는 사용자 승인으로 이미 반영되었다. 이 문서의 UI 개선 사항은 제안이며 아직 구현하지 않았다.
