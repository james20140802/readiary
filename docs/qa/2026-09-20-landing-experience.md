# 랜딩 체험과 클릭 결과 일치 검증

관련 이슈: [랜딩에서 안내한 체험과 클릭 결과를 일치시킨다](https://app.notion.com/p/3d5eedeede868114bec5d1560774bb40)

## 변경한 경험

- 책등을 누르면 기존 책장과 같은 책 꺼내기·표지 펼치기를 체험한다. 덮기, Escape, 다른 책 전환을 지원하며 덮은 뒤 책등으로 포커스를 돌린다.
- 펼친 견본의 제목·표지는 가입 링크가 아니다. 견본 책 안의 가입 버튼은 사용자 피드백에 따라 제거했다. 일반 책장의 상세·기록 링크는 유지한다.
- 자동 타이핑을 실제 문장·생각 입력으로 바꿨다. 책 선택과 비공개 선택을 샘플 결과에 반영하고, 생각·문장·쪽수 추가와 수정·취소가 동작한다.
- 같은 샘플 기록의 문장을 발췌집으로 열고 다시 기록으로 돌아온다. 생각만 있는 기록에는 문장 추가 안내를 제공한다.
- 샘플 입력은 컴포넌트 메모리에만 유지하며 API, DB, 로컬 저장소에 저장하지 않는다. 입력 앞의 샘플 안내 문구는 사용자 피드백에 따라 제거했다. 실제 계정 가입·저장과 샘플 결과를 구분한다.
- 설명의 `max-w-prose` 제한을 없애 본문 너비를 활용하고 한국어 어절을 유지한다.
- 동작 줄이기에서 SSR 초기 투명도가 남는 현상을 재현했다. 서버와 hydration의 미디어 설정을 일치시키고 모션을 끌 때 투명도·변환의 최종값을 명시한다.

## 확인한 조건

로컬 Next.js 개발 서버와 Playwright Chromium의 비로그인 브라우저에서 확인했다. 실제 모바일 기기 검증은 아니다.

| 조건 | 결과 |
| --- | --- |
| 1440×1000, 라이트 | 문장 편집 → 샘플 남기기 → 생각·42쪽 추가 → 같은 문장의 발췌집 → 기록 복귀. 책 펼침. 설명 전체가 한 줄로 이어짐 |
| 390×844, 라이트 | 생각만 저장, 책·비공개 선택, 문장 추가, 잘못된 쪽수 거부, 발췌집, 책 전환·덮기 통과 |
| 320×740, 다크, 동작 줄이기 | 초기 투명도 문제 수정 후 전체 흐름 재검증. 제목·본문 opacity 1 확인, 긴 문장 가로 넘침 없음 |
| 844×390, 다크 | 짧은 가로 화면의 내부 스크롤로 결과·발췌집 버튼 도달, 책 전환·덮기 통과 |
| 키보드 | Enter로 샘플 남기기·책 열기, 편집 Escape 취소와 원래 칩 포커스 복귀, 책 Escape 닫기와 책등 포커스 복귀 |
| 입력 경계 | 문장·생각 모두 공백이면 남기기 비활성. 생각만 있어도 저장. 음수 쪽수는 브라우저 검증으로 차단. 긴 연속 문자열도 가로 넘침 없이 표시 |

책은 모달이 아닌 기존 인라인 펼침이므로 포커스를 가두지 않는다. 좁은 책의 조작부는 내부 스크롤을 사용하며, 덮기 포커스 시 해당 버튼이 보이도록 스크롤한다.

## 저장소 검사와 한계

- Vitest: 57개 파일, 393개 테스트 통과.
- ESLint: 오류 없음. 기존 경고 4개(댓글 effect 2개, Supabase 운영 테스트 console 2개).
- TypeScript, 변경 파일 Prettier, `git diff --check` 통과.
- 프로덕션 빌드 통과: 기존 로컬 환경 공급 경로를 읽어 실행. 환경 파일 복사·값 출력 없음.
- 로그인된 실제 계정, 실제 저장/DB, iOS 설치형 PWA, VoiceOver는 미검증이다. 로그인한 사용자의 `/` → 대시보드 리디렉션 코드는 변경하지 않았다.
- 머지·프로덕션 배포는 별도 단계다.

## 태블릿 실화면 피드백 후 배치 보정

사용자가 제공한 iPad 브라우저 사진에서 회고의 2열 압축, 책 왼쪽의 세로 제목, 넓은 입력창의 고정 2줄을 확인했다.

- 회상·주간·월별 카드를 모든 폭에서 세로로 나열한다. 월별 카드를 모바일에서도 표시한다. 공용 주간 카드의 `이번 주 문장`은 한 줄로 유지하고, 아주 좁으면 숫자·라벨 묶음이 다음 줄로 이동한다.
- 책장 안내는 `책등을 눌러 책을 펼쳐 보세요.`만 남긴다.
- 공용 OpenBook의 표지 없는 책은 왼쪽 제목·저자를 가로 중앙 정렬한다. 실제 책장·프로필 책장에도 같은 대체 표지가 적용되며 표지 이미지가 있는 책은 유지한다.
- 실제 Composer의 하단 배치를 ComposerControls로 추출해 랜딩과 공유한다. 원래 ref·ResizeObserver·책 칩 우선순위 및 버튼 크기를 유지한다. 랜딩의 기본 입력도 실제 입력창과 같은 17px 서체·배경·구분선으로 맞춘다. 랜딩에는 샘플 책 두 권만 제공한다.
- Tailscale HTTPS의 1280·768px에서 책 칩과 문장·생각·비공개·남기기 버튼이 같은 줄임을 좌표로 확인했다. 390·320px에서는 책 선택만 윗줄, 조작 버튼은 한 줄로 유지한다.
- 네 폭에서 회고 카드의 세로 순서와 가로 넘침 없음, 펼친 제목의 가로쓰기, 샘플 저장 → 발췌집과 Escape 닫기를 확인했다. 라이트·다크와 동작 줄이기를 포함한다.
- 수정 후 TypeScript, ESLint(기존 경고 4개), 테스트 393개, 프로덕션 빌드가 다시 통과했다. 수정 후 실제 iPad 재확인은 사용자 확인 전이며 위 자동 검증은 데스크톱 Chromium이다.

## 후속 문구 정리

- 입력 앞의 샘플 안내와 연결된 aria-describedby를 제거했다. 샘플의 메모리 저장 방식은 유지한다.
- 견본 책의 가입 링크를 제거하고 덮기 버튼은 오른쪽에 유지한다. 일반 책의 상세·기록 링크는 유지한다.
- 마지막 장서표 버튼은 `시작하기`로 줄였다.
- 랜딩 길이와 핵심 장면 구성은 다음 이슈에서 별도로 검토한다.
