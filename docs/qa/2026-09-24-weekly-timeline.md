# 이번 주의 기록 타임라인

## 달라지는 읽기 경험

알림에서 들어오는 `/protected/notifications/weekly`의 반복 테두리 카드를 날짜별 원고 흐름으로 바꾼다. 날짜는 각 묶음에서 한 번 표시하고, 같은 날의 기록은 가는 구분선으로 나눈다. 문장은 마루 부리 `text-quote`, 생각은 `text-note`로 함께 보여 준다. 문장 6줄·생각 4줄 이후는 말줄임하며, 기록 전체를 누르면 기존 기록 상세로 이동한다.

조회는 기존과 같이 최근 7일 이내 생성한 소유자 기록 최대 50개다. 가져온 기록을 사용자가 지정한 `date`의 내림차순으로 묶고, 같은 날짜 안에서는 기존 생성 시각 내림차순을 유지한다. 과거 날짜로 소급해 남긴 기록도 조회 대상에 포함될 수 있다. 50개 상한 안내를 유지하며 전체 기록 수로 표현하지 않는다.

## 디자인과 동작의 기준

- 시각 기준: `docs/ui-guidelines.md`. 런타임 값은 `app/globals.css` → `tailwind.config.js` → 기존 UI 컴포넌트를 따른다. 전역 디자인 결정이나 토큰을 바꾸지 않는다.
- 뒤로 가기: 기존 `BackButton`. 상세 이동: 기존 `/protected/entry/[id]` 링크. 최대 50개의 상세 요청을 미리 발생시키지 않도록 기록 링크의 프리페치를 끈다.
- 빈 화면: 기존 `Button`으로 오늘 화면의 기록 작성에 연결한다.
- 조회 오류: 오류와 복구 안내를 표시하고 같은 URL을 새로 요청하는 링크를 제공한다.
- 로딩: 읽기 전용 스켈레톤과 상태 문구. 모션 감소 설정에서는 점멸하지 않는다.
- 인증·소유자 필터·RLS·알림 확인 처리는 기존 경로를 유지한다.

## 검증

- Vitest: 71개 파일, 466개 테스트 통과.
- 승인된 환경 공급 경로로 프로덕션 빌드 통과(환경 파일 복사 없음).
- TypeScript 통과. ESLint 오류 0개, 기존 경고 4개.
- 합성 기록을 실제 Chromium에서 320px·390px·1280px, 라이트·다크로 확인. 가로 넘침 없음.
- 4개 기록이 3개 날짜로 묶이며 날짜가 한 번씩 표시됨. 문장과 생각 동시 표시, 생각만 있는 기록, 긴 제목·긴 어절·줄바꿈·말줄임 확인.
- 뒤로 가기에서 Tab으로 첫 기록 링크에 이동하고 포커스 링이 표시됨. 상세 링크 목적지 확인.
- 빈 화면의 작성 링크, 오류 화면의 재요청 링크, 로딩 문구와 모션 감소 설정 확인.
- Premium 정적 감사: 변경 파일 지적 0개. 저장소 전체 strict 감사는 기존 9개 항목으로 실패(다른 화면의 버튼·폼과 전역 스크롤바). 이번 변경의 통과로 표현하지 않는다.

합성 미리보기 라우트는 검증 후 제거했다. 실제 로그인 데이터, 실제 상세 이동 후 화면, 운영 네트워크 실패·재시도 성공, 실제 알림 클릭, iOS 설치형 PWA와 실기기 조작은 미검증이다. 머지·운영 배포는 이 변경에 포함하지 않는다.

## 독서 편지 이미지 내보내기 (추가)

주간 타임라인에서 `독서 편지로 내보내기`를 누르면 같은 화면 안에서 기록을 고른다. 기본 선택은 없으며 생각 포함 여부를 바꿀 수 있다. 생각만 있는 기록은 생각 제외 시 내보내기 대상에서 빠진다. 비공개 기록은 선택 목록과 선택 개수 안내에 표시한다. 편지에는 선택한 기록을 날짜 오름차순으로 담는다.

- 생성 파일: 기존 `LIGHT_PALETTE`를 사용하는 1080 × 1520 PNG. 고정 밝은 종이, 기간, 책 제목, 문장/생각, 장 번호를 포함한다. 표시 기간은 화면 조회의 최근 7일이며, 소급해 기록한 날짜는 본문에 그대로 남긴다.
- 실제 글꼴의 렌더 높이를 측정해 여러 장으로 조판한다. 긴 본문은 `이어서` 표기와 함께 다음 장으로 넘긴다. 원문의 줄바꿈·공백·이모지를 보존하며 말줄임하지 않는다. 최대 30장을 넘거나 제목 등 메타데이터 자체가 한 장보다 크면 선택을 유지하고 명확한 오류를 표시한다.
- 동적 import로 선택 화면과 이미지 생성기를 필요할 때 불러온다. 새 후보 조회 없이 이미 읽은 최대 50개 기록을 사용한다.
- 생성 중 돌아가면 남은 캡처를 중단한다. 중복 생성은 동기 action lock으로 막고, 실패 시 선택을 유지한다. Blob URL은 다시 선택·닫기·언마운트·부분 실패에서 해제한다.
- 완성 이미지마다 별도 저장 링크를 제공해 브라우저의 연속 다운로드 차단을 피한다. 지원 기기에서는 사용자가 `편지 공유하기`를 누를 때 OS 공유창을 연다. 미지원·실패 시 이미지 저장으로 안내하고 취소는 오류로 표현하지 않는다.

### 개인정보와 공개 범위

이미지는 브라우저 메모리에서 만들고, 사용자가 저장하거나 OS 공유창으로 전달한다. 생성·미리보기만으로 업로드나 메시지 발송은 발생하지 않는다. `enable_entry_share` 등 RPC, `shared_at`, `is_private`, Storage, 친구 접근 권한을 변경하지 않는다. 생성 파일에 계정 식별자·공유 링크를 넣지 않는다. 기록 ID는 화면 내 그룹 식별에만 쓰고 이미지에는 담지 않는다. 파일은 앱의 공유 해제와 별개로 남는 사본이다. 미리보기에서는 다른 사람에게 전달하면 이미지에 담긴 내용을 볼 수 있음을 안내한다.

주간 경로는 기존 소유자 필터와 인증을 사용하며, `is_private` 필드를 비공개 표시를 위해 함께 조회한다. API·DB/RLS·Storage 변경 없음. 기존 PWA의 문서/RSC/API/Supabase `NetworkOnly` 규칙을 유지한다. 추가한 데이터 영속화, localStorage/IndexedDB/Cache Storage 쓰기, 이미지 업로드 경로는 없다.
