# 홈에서 작성 중인 문장 이어 쓰기

홈 작성기는 기존 책 칩과 ‘내 책’의 책장 이동을 유지한다. 책 칩을 바꾸거나 같은 탭에서 다른 화면을 다녀와도 문장과 생각을 각각 자동으로 복원한다. 홈 안의 추가 책 검색, 정상 보관 안내, 초안 버리기 버튼은 사용자 요청으로 제거했다. 복원된 책이 현재 목록에 없으면 입력을 유지하며 저장은 다른 칩을 선택한 뒤 가능하다.

## 보관 범위

- 같은 탭의 `sessionStorage`에 계정 식별자, 선택한 책 ID, 문장, 생각, 입력 모드, 비공개 설정을 한 초안으로 보관한다. 저장을 시작할 때 요청 UUID·원래 기록 날짜·책 제목도 함께 보관한다. 본문 입력은 화면 이동 전 바로 기록한다.
- 새로고침도 복원하지만 탭 종료 후 복원·다른 기기 동기화는 보장하지 않는다. 브라우저의 세션 복구 동작에 따라 보관 기간이 달라질 수 있다.
- 저장 성공과 입력 내용을 모두 지웠을 때, 로그아웃·계정 전환 때 정리한다. 서버가 늦게 응답하면 제출했던 초안과 일치할 때만 제거해 이후 작성한 초안을 보호한다.
- 인증 초기 이벤트에서 계정이 일치하기 전에는 초안을 표시하거나 입력·저장하지 않는다. 앱 셸은 작성기가 없는 화면에서도 인증 변경을 받아 초안을 정리한다.
- 저장 공간 차단·용량 오류가 나면 화면의 입력은 유지하고 보관 실패를 안내한다. 요청 ID를 보관할 수 없으면 전송을 시작하지 않아, 새로고침 뒤 확인할 수 없는 저장을 만들지 않는다.
- 범위는 홈의 최초 저장 전 초안이다. 저장 후 덧붙이기, 별도 기록 등록·수정 폼은 이 저장소를 사용하지 않는다.

## 응답 유실·재시도와 중복 방지

- 최초 요청 전에 UUID를 생성해 초안에 보관한다. 전송한 요청의 날짜·책·문장·생각·공개 설정은 결과가 확정될 때까지 고정한다. 클릭 핸들러 진입 즉시 ref 잠금을 걸어 같은 렌더의 빠른 연속 클릭도 한 요청으로 제한한다.
- 저장 중에는 진행 상태를 표시한다. 15초 응답 제한, 네트워크 오류, 서버 오류, 읽을 수 없는 응답은 성공으로 취급하지 않고 초안과 요청 ID를 유지한다. 새로고침 후에도 `저장 확인·재시도`로 같은 요청을 이어 보낸다.
- 서버의 `/api/entries/new`는 선택적인 `client_entry_id`를 검증해 기존 `entries.id` PK에 사용한다. 동시 요청의 PK 충돌은 소유권을 확인한 동일 `user_book_id`의 기록을 읽어 기존 ID를 반환한다. 기존 기록을 UPDATE/upsert로 덮어쓰지 않는다. 요청 ID가 없는 기존 등록 폼의 동작은 유지한다.
- insert 후 진행률 갱신에서 실패한 요청도 재시도에서 갱신을 마무리한다. 책 확인 DB 오류는 권한 거절과 구분해 503으로 반환한다.
- 저장 확인·재시도는 아직 기록이 없으면 저장하고, 이미 있으면 기존 기록을 확인한다. 따라서 응답 유실 여부를 독자가 추측해서 새 기록을 만들 필요가 없다. 내 책장에서 직접 확인하는 링크도 제공한다.
- 서버가 명확히 거절한 400·403 응답은 요청 고정을 해제해 입력을 수정할 수 있다. 나머지 불확실한 결과는 같은 ID를 유지한다. 성공 시 완료 안내·기록 보기 링크를 표시하며 초안을 지운다. 화면 복귀 뒤 늦게 성공한 경우에도 일치하는 초안만 지우고 완료 Toast를 알린다.
- 이 중복 방지는 동일 요청 ID와 남아 있는 기록에 대한 보장이다. 명시적 폐기·로그아웃·브라우저 저장소 삭제 후 새로 작성한 요청, 기존 기록을 직접 삭제한 뒤의 재작성은 별개의 행동이다.

## 개인정보·데이터 경계

초안은 저장 행동 전 서버/API·분석 로그로 전송하지 않으며 DB나 Storage에 저장하지 않는다. 개인정보처리방침의 서버에 보관하는 독서 기록과 구별되는 탭 내 임시 입력이다. 정상 보관 안내는 표시하지 않는다. PWA/Workbox 응답 캐시를 초안 저장에 사용하지 않는다.

저장 API의 `getUser()`·책 소유권 확인과 기존 공개 범위 처리는 유지한다. `is_private=false`는 친구 열람 범위이며 초안 보관이 외부 공유를 만들지는 않는다. DB 마이그레이션·Storage 정책 변경은 없다.

- Vitest 53파일 371테스트 통과. 초안·미확정 요청 복원, 다른 계정 배제, 손상값, 폐기, 늦은 저장 응답, 저장소 오류 테스트 포함. API 테스트는 DB 클라이언트 대체를 사용해 동시 재시도·응답 유실·진행률 후속 실패·소유권·기존 기록 비덮어쓰기를 검증했다.
- TypeScript 통과. ESLint 오류 0, 기존 경고 4.
- 실제 Composer와 초안 훅을 사용한 로컬 Chrome 검증 화면에서 인증·DB/API 응답을 대체했다. 390px 라이트·다크, 1440px 화면을 확인했다.
- 문장/생각 독립 유지, 책 칩 선택, 화면 언마운트·재마운트와 새로고침 복원, 비공개 설정 유지, 실패 시 입력 유지, 성공 후 초안 삭제, 계정 변경·로그아웃 비움 확인.
- 추가 기준: 빠른 3회 클릭에서 전송 1회, 서버 저장 뒤 응답 유실→새로고침→같은 ID 재시도에서 저장 행 1개, 15초 시간 초과 후 재시도·완료를 로컬 대체 응답으로 확인했다.
- 사용자가 요청한 `.env.local` 복사 후 `npm run build` 전체 통과. 환경 파일은 Git에서 제외한다.
- 실제 인증·운영 DB 통합, iOS 설치형 PWA 실기기, 프로덕션 배포는 미검증이다. 로컬 대체 응답 검증을 실서비스 검증으로 보지 않는다.


- 최종 UI 단순화: 기존 책 칩과 내 책장 이동 코드를 복원하고 선택기를 제거했다. 390px 라이트·다크에서 안내·폐기 버튼이 없는 배치, 키보드 책 선택, 화면 복귀·새로고침 입력 복원을 대체 인증 환경에서 확인했다. 최종 변경 뒤 371테스트·TypeScript·변경 파일 ESLint 통과.

## 책장에서 바로 기록하기

책 비율·안쪽 여백·하단 링크 위치와 스타일은 기존 그대로 유지한다. 기존 `책 상세 →` 자리만 `기록 남기기 →`로 바꾸어 해당 책의 작성 화면에 연결한다. 책 제목과 왼쪽 표지는 책 상세로 이동하며 덮기는 기존 동작을 유지한다.

실제 OpenBook과 예시 책으로 모바일 다크 화면에서 하단 링크와 표지의 클릭 가능 여부, 기록 링크의 Enter 이동을 확인했다. TypeScript·ESLint 통과. 실제 인증된 작성 폼과 iOS 실기기 통합은 미검증이다.
