# 책과 기록 다시 찾기

책장 검색 입구와 전역 돋보기는 `/protected/search`로 연결된다. 하단 내 책 탭을 유지한다.

## 검색 범위와 표시

- 로그인한 본인의 책 제목·저자와 기록의 문장·생각만 검색한다. 친구 기록은 포함하지 않는다. 본인 비공개 기록과 기록 없는 책은 포함한다.
- 앞뒤 공백을 제거한 표현의 부분 문자열을 찾는다. 대소문자는 무시하고 내부 공백·특수문자는 리터럴로 취급한다. 형태소·유사 의미·단어별 AND 검색은 제공하지 않는다.
- 한글 조합 종료 후 300ms에 자동 검색하며 Enter/검색 버튼으로 즉시 실행할 수 있다. 빈 검색어에서는 결과 영역을 비워 두며, 검색 후 일치하는 결과가 없을 때만 안내한다.
- 전체 탭은 책 3권과 기록 목록을 표시한다. 책 더 보기는 책 탭으로 전환한다. 책·기록은 각각 20개씩 커서로 추가 조회한다.
- 책 결과는 등록 최신순, 기록은 기록 날짜 최신순이다. 기록은 생성 시각과 ID, 책은 ID로 동률을 해소한다.
- 검색 화면에는 검색어와 전체·책·기록 구분만 제공한다. 책·날짜 필터와 책 선택기는 사용성 피드백에 따라 제거했다. API의 선택적 필터 계약은 유지하지만 화면에서는 전송하지 않는다.
- 기록에 일치한 문장·생각 주변만 표시하고 양쪽 일치는 한 기록으로 합친다. 책 제목 일치는 그 책의 모든 기록을 자동 포함하지 않는다.
- 기존 책/기록 상세로 이동한다. 뒤로 가면 현재 탭 메모리에서 검색 조건·펼친 목록·스크롤을 복원한다. 새로고침은 초기화한다.

## API와 권한

`POST /api/search`는 JSON `{ query, kind, bookId?, from?, to?, cursor? }`를 받는다.

- `kind`: `books`, `entries`, `candidates`. `bookId`는 필터 대상 **user_books.id**이다.
- 응답: `{ items, next }`. 책 항목의 `id`는 `user_books.id`, `bookId`는 상세 경로용 `books.id`이다.
- `next`: `{ id, created, date? }` 또는 `null`. 서버에서 조건과 커서 타입을 검증한다.
- 검색어 최대 200자, 대상별 응답 최대 20개. 후보 조회에서만 빈 검색어를 허용한다.
- `search_library` RPC는 `security invoker`로 기존 RLS를 유지하고 `auth.uid()` 소유 조건을 추가한다. 익명 실행 권한은 없다.
- 검색어를 URL이나 분석 이벤트에 기록하지 않는다. 응답은 `private, no-store`; 기존 PWA 개인화 요청 `NetworkOnly` 규칙을 유지한다.
- 조건과 결과는 브라우저 탭 메모리에만 남긴다. AppShell의 인증 이벤트가 로그아웃/계정 전환 시 지우며, 늦은 요청은 취소하거나 무시한다.
- 외부 검색 서비스, Storage 변경, 공개 범위 변경은 없다.

## 적용과 검증

앱 배포 전에 `20260915000000_search_library.sql`을 대상 DB에 적용해야 한다. 함수가 없으면 검색은 오류와 재시도를 표시한다. 2026-09-15 사용자 요청으로 운영 `readiary` 프로젝트(`piqlggyuhhicnjywombg`)에 적용했다. 운영 이력 버전은 `20260915123044`, 이름은 `search_library`다. 적용 전 함수 부재를 확인했고, 적용 후 함수 정의·security invoker·빈 search_path·익명 실행 불가·authenticated 실행 가능을 읽어 확인했다. 실제 책·기록을 authenticated 역할로 조회하여 예상 결과 수와 기록 소유자 제한을 검증했다. 기존 데이터 수정은 없다.

- `npm test`: 검색 입력·문자 강조·계정별 메모리·API 권한/캐시/오류 계약을 포함한다.
- `npm run lint`, `npx tsc --noEmit`, 환경 공급 후 `npm run build`.
- `PGLITE_MODULE=<PGlite 모듈 절대경로> node supabase/tests/run-search-contract.mjs`: 독립 인메모리 PostgreSQL에서 본인/다른 계정, 비공개 기록, 리터럴 검색, 날짜 경계, 동률 페이지네이션, 긴 본문 스니펫을 확인한다. 운영 DB에 테스트 데이터를 넣지 않는다.

2026-09-15 로컬 Chromium 검증은 **합성 계정·로컬 백엔드·검색 API fixture**를 사용했다. 실제 제품 컴포넌트와 검색/상세/책장 경로를 실행했다.

- 320·390·768·1440px, 라이트·다크에서 가로 넘침 없음.
- 입력 → 검색 → 지우기 → 전체/책/기록 → 필터 키보드 순서, 책 선택 후 트리거 포커스 복귀.
- 한글 composition 이벤트 중 요청 없음, 완료 후 검색, 늦은 응답 무시.
- 빈 결과, 기록 오류 중 책 성공, 재시도, 날짜 오류, 책 선택·초기화, 20→22개 추가 조회.
- 추가 조회 도중 탭을 바꾸고 복귀한 뒤 재조회 가능.
- 기록 상세에서 돌아오면 검색어·책 필터·22개 목록과 스크롤 2361px 복원.
- 책장 입구에서 같은 검색 화면으로 이동.

실제 로그인 브라우저와 운영 Supabase 통합, 운영 규모 쿼리 실행 계획/지연, iOS 설치형 PWA, 보조기기 실제 읽기, 사용자 재탐색 과제는 별도 확인이 필요하다. 사용자 과제는 책 제목을 가린 상태에서 기억나는 표현만으로 기록을 찾아 원문을 여는 것이다.

## 모바일 검색 UI 보완 (2026-09-15)

- 기존 괘선 입력·부리 본문·먹 버튼·의미 색상 토큰을 유지했다. 별도의 시안 이미지는 기존 디자인 시스템 안의 국소 수정이므로 생성하지 않았다.
- 지우기는 입력 안의 X 버튼, 실행은 명시적인 검색 버튼으로 정리했다. 입력 전후 조작부 높이가 바뀌지 않는다. 모바일 키보드에 검색 동작을 표시한다.
- 전체/책/기록은 책장과 같은 밑줄 선택 표현으로 바꾸고, 필터와 같은 줄에 배치했다. 주요 조작부 높이는 실제 렌더링에서 44px 이상이다.
- 480px 미만에서는 날짜를 세로로 배치하고, 긴 선택 책 제목은 줄바꿈한다. 당시 넓은 화면은 본문 폭을 672px로 제한했으며, 아래 2026-09-18 수정에서 공통 페이지 폭으로 통일했다.
- Chrome 브라우저 도구로 320/390/768px 화면과 책 선택을 확인했다. 테마 에뮬레이션을 지원하지 않아 Playwright Chromium으로 320/390/768/1440px 라이트·다크를 보완했다. 합성 계정과 로컬 RPC fixture를 사용했고 실제 앱 API 경로를 통과했다.
- 검색→지우기→검색 대상→필터 순서, 44px 이상 터치 영역, 긴 책 제목과 날짜 입력의 가로 넘침 없음, 선택 후 포커스 복귀를 확인했다. 빈 결과·부분 오류·재시도·지연·날짜 오류·20→22개 추가 조회·상세 복귀도 확인했다. 오류 시나리오의 500 및 합성 알림 백엔드의 CORS 오류는 운영 검색 오류와 구분했다.
- 이전/이후 캡처에서 입력과 버튼 정렬, 조작부 간격, 부리/산세리프 역할, 라이트/다크 토큰, 좁은 화면 줄바꿈을 비교했다. 의도한 문구 변경은 검색 버튼 텍스트, 짧은 입력 힌트, 필터의 짧은 시각 라벨이며 접근성 이름은 유지했다.
- Premium 정적 감사의 기존 8건(다른 화면 버튼/폼 및 공용 스크롤바)은 별도 개선 범위다. 이 검색 컴포넌트에는 지적이 없었다. 프로젝트 가이드는 `docs/ui-guidelines.md`, 런타임 토큰 소유자는 `app/globals.css`이며 중복 DESIGN 문서는 만들지 않았다.
- iOS 설치형 PWA·실기기·보조기기와 실제 로그인한 운영 브라우저 흐름은 미검증이다.

## 페이지 구성 통일 (2026-09-18)

- 검색 전용 최대 너비를 제거하고 책장과 동일한 AppShell 너비·좌우 여백을 따른다.
- 제목 왼쪽에 기존 공용 BackButton을 배치했다. 방문 기록이 있으면 이전 화면, 없으면 오늘 화면으로 이동하는 기존 동작을 재사용한다.
- 합성 계정 Chromium에서 320·390·768·1440px 라이트/다크 모두 책장과 검색 본문의 너비·시작 좌표가 일치하고 가로 넘침이 없음을 확인했다. 실제 본문 너비는 각각 288·358·736·736px였다.
- 책장에서 검색 진입 후 뒤로 가기 버튼을 Enter로 실행해 책장 복귀, 뒤로 가기에서 Tab으로 검색 입력 이동, 검색 성공 결과를 확인했다. 실기기·iOS PWA는 미검증이다.

## 검색 필터 제거 (2026-09-18)

- 책·날짜 필터 버튼, 접힌 패널, 책 후보 선택기를 제거했다. 검색어와 전체·책·기록 구분에 집중한다.
- 브라우저 탭의 검색 상태에서 책·날짜·패널 열림 상태를 제거하고 기록 요청에 해당 조건을 보내지 않는다. 빈 결과 안내에서도 필터 언급을 없앴다.
- 기존 API/RPC의 선택적 필터 계약과 권한 검증은 유지한다. DB 마이그레이션 변경은 없다. 이전 절의 필터 검증은 제거 전 이력이다.
- 합성 계정 Chromium 320·390·768·1440px 라이트/다크, 키보드 순서·지우기 포커스, 빈 결과·부분 오류/재시도·로딩·성공·20→22개 추가 조회·상세 복귀를 확인했다. 요청에 책/날짜 조건이나 후보 조회가 없었다. 388개 테스트 통과. 실기기·iOS PWA는 미검증이다.
