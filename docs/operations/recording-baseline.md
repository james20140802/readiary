# 첫 기록과 후속 기록 기준값 집계

운영자는 새 추적 도구 없이 현재 남아 있는 데이터로 기록 이용 현황을 확인할 수 있다.
[집계 SQL](../../scripts/recording-baseline.sql)은 조회만 수행하며 앱, DB 스키마, RLS를 변경하지 않는다.
PostHog 도입은 별도의 이벤트 수집 작업이다. 이 집계로 과거 방문·클릭·이탈 원인을 복원할 수는 없다.

## 실행과 제외 목록

1. SQL을 저장소 밖의 비공개 실행 공간에 복사한다.
2. `params.cutoff`에 집계 기준 시각을 시간대가 명시된 값으로 지정한다. 기본값은 최초 조사 기준이며 재실행 시 의도적으로 결정한다.
3. 별도 비공개 UUID 목록을 관리하고 `params.excluded`의 빈 UUID 배열에 적용한다. 목록 버전, 담당자, 제외 사유(운영자/테스트)를 비공개 운영 기록에 남긴다. 이메일·닉네임 패턴으로 추정하지 않는다.
4. 승인된 운영 DB 연결에서 읽기 전용으로 실행한다. 개인 UUID 목록·실행용 SQL·운영 결과는 공개 Git/PR에 넣지 않는다. DB 식별자나 환경 파일을 복사할 필요가 없다.
5. 비공개 보고서에 cutoff, 실제 실행 시각, 쿼리 커밋, 목록 버전, 목록 크기, 실제 제외 수, 분모와 인원수를 남긴다. 목록에 있지만 대상 계정에 없는 ID가 있으면 원인을 확인한다.

목록을 아직 받지 않았다면 빈 배열로 실행할 수 있지만 반드시 **전체 계정 기준 잠정 집계 / 운영자·테스트 미제외**로 표시한다. 실사용자 전환율로 해석하거나 이슈를 완료 처리하지 않는다.
목록은 코드와 분리해 유지하고, 이후 집계에도 같은 버전을 적용할 수 있어야 한다.
이 쿼리는 인증된 운영자의 수동 조사용이며 클라이언트 API나 공개 RPC로 노출하지 않는다.

## 지표 정의

기준 시각 미만에 가입한 현존 비삭제·비익명 계정 중 제외 목록에 없는 계정이 모집단이다.
기간은 서비스 시작부터 cutoff 직전까지다. 각 계정은 지표별로 한 번만 센다.

| 결과 필드 | 의미와 분모 |
| --- | --- |
| accounts | 모집단 계정 수 |
| with_profile | cutoff 이전 profiles 행이 남아 있는 계정 / accounts |
| with_book | cutoff 이전 user_books 행이 하나 이상 남아 있는 계정 / accounts |
| with_first_record | cutoff 이전 entries 행이 하나 이상 남아 있는 계정 / accounts |
| with_followup_record | 기록이 두 건 이상 남아 있는 계정 / with_first_record; 같은 날도 포함 |
| multiple_kst_days | 한국 시간으로 서로 다른 날짜에 기록한 계정 / with_first_record |
| repeat_denominator | 첫 현존 기록 후 336시간 이상 관찰된 계정 |
| repeat_numerator | 위 분모 중 첫 기록 후 168시간 이상, 336시간 미만에 기록한 계정 |
| repeat_pending | 기록은 있으나 336시간 관찰이 끝나지 않은 계정 |
| signup_to_first_median_hours | 첫 기록 계정 중 시간 역전이 없는 계정의 가입→첫 현존 기록 소요 시간 중앙값 |

프로필 존재는 현재 온보딩 완료의 대리 지표다. 단계별 수는 각각의 도달 수이며 역사적 순서가 보장된 이벤트 퍼널이 아니다.
재기록 기간은 달력 주가 아닌 경과 시간이다. 날짜 구분만 Asia/Seoul을 사용한다.
기록 시점은 entries.created_at이며 사용자가 입력한 entries.date를 사용하지 않는다.
quote와 note가 함께 있는 행도 한 건이며, 본문은 조회하지 않는다. 과거 형식의 기록도 entries 행으로 센다.

## 한계와 품질 확인

- 삭제된 계정·책·기록은 복원되지 않는다. 첫 현존 기록은 생애 최초 기록과 다를 수 있다. 같은 cutoff로 나중에 실행해도 삭제 때문에 결과가 바뀔 수 있다.
- 가입 수는 인증 완료나 방문 수와 같지 않다. 실제 방문·클릭·세션·저장 응답 수신 여부는 알 수 없다.
- 서로 다른 날짜에 기록했다는 사실만으로 재방문 세션을 증명하지 않는다.
- 저장된 행을 세므로 버튼 클릭·실패·같은 ID의 재시도 응답은 추가 기록이 아니다. 과거 다른 ID로 중복 저장된 행은 식별할 수 없다.
- created_at 누락은 해당 시점 지표에서 제외된다. missing_entry_times, first_before_signup을 확인하고 이상이 있으면 시간 지표 해석을 보류한다. auth.users/profiles/user_books의 시각 누락과 미래 시각도 별도 점검한다.
- UTC 기반 timestamptz로 비교한다. 현재 DB 시간대가 UTC임을 확인하되, 과거 쓰기 세션의 시간대까지 증명한 것으로 해석하지 않는다.
- 작은 표본은 비율만 보고하지 않는다. 인원수와 관찰 대기 수를 함께 남긴다. 가입 코호트별 고정 기간 전환율은 이 누적 기준값과 별도 지표다.

## 검증

운영 DB에서 개인정보나 본문 없이 집계 SELECT를 실행했다.
[합성 데이터 경계 검증 SQL](../../scripts/recording-baseline-fixture.sql)은 운영 테이블을 참조하지 않는 CTE만 사용한다.
기대 결과는 accounts=3, repeat_denominator=2, repeat_numerator=1, repeat_pending=1이다.
7일 경계는 포함하고 14일 경계는 제외하며, 정확히 14일 관찰한 계정은 분모에 포함한다.
합성 계정 1의 UUID를 중복 두 번 제외 배열에 넣으면 목록 크기와 실제 제외 수는 각각 1,
accounts=2, repeat_denominator=1, repeat_numerator=0, repeat_pending=1이어야 한다.
두 경우 모두 운영 PostgreSQL에서 기대값을 확인했다. 앱 동작 변경이 없어 UI·배포·기기 검증은 해당하지 않는다.
