# 책과 기록 삭제

독자는 본인 책 상세 상단 오른쪽 **책 관리(⋯) → 책 삭제**에서 확인창을 열고 **책과 기록 삭제**를 선택한다.
기록이 없는 책도 같은 방식으로 삭제한다. 다른 독자의 책 상세에는 버튼을 표시하지 않는다.
확인창은 문장·생각·덧붙인 생각·댓글·좋아요와 공유 링크에 미치는 영향, 복구 불가를 안내한다.
요청 중에는 중복 제출·취소·Esc·바깥 클릭으로 닫기를 막고, 오류는 창 안에서 재시도를 제공한다.
성공하면 내 책장으로 새 문서 이동한다.

## 데이터와 권한

`DELETE /api/books/[user_book_id]`는 `auth.getUser()`로 인증하고, 등록 ID와 인증된
사용자 ID를 모두 조건으로 `user_books`를 한 번 삭제한다. `user_books_delete_own` RLS도
본인 소유 조건을 강제한다. 다른 사용자의 항목과 이미 없는 항목은 동일한 204로 응답한다.
응답 유실 후 재시도는 안전한 no-op이며, 같은 책을 재등록하면 등록 ID가 달라 이전 요청이
새 책장 항목을 삭제하지 않는다. 브라우저 자동 재시도는 기존 세션 갱신 경로만 사용한다.

2026-10-12 운영 DB의 외래키와 책장 RLS를 읽기 전용으로 확인했다. 기존 연결 규칙을
사용하므로 이 기능에 새 마이그레이션은 없다.

- `user_books → entries → entry_reflections / comments / likes / notifications`: cascade 삭제.
- 댓글 답글과 댓글 기반 알림도 cascade 삭제.
- `profiles.featured_entry_id`, `profiles.bookmark_user_book_id`: null로 초기화.
- `push_finished_receipts`: cascade 삭제.
- 공용 `books`와 다른 사람의 같은 책 등록·기록은 유지.
- 등록 요청 중복 방지 이력은 기존 정책대로 유지하여 이전 등록 요청의 재전송이 책을 되살리지 않게 한다.

PostgreSQL 한 문장이므로 연결 데이터 삭제 실패 시 전체가 롤백된다. 새 기록 작성과 경합할 때도
외래키가 부모 없는 기록의 저장을 막는다. 확인창은 특정 시점의 건수가 아니라 해당 책의 **모든**
기록 삭제를 확인하므로, 삭제 전에 다른 탭에서 저장된 기록도 범위에 포함한다.

## 공유·Storage·캐시

친구 열람과 외부 공유 링크는 모두 원본 기록을 조회하므로 삭제 뒤 새 조회에서 사라진다.
외부 공유 조회는 기존 `get_public_entry` 및 `cache: no-store`를 유지하며, OG 이미지도
`private, no-store`다. 책 삭제는 Storage 객체를 만들거나 삭제하지 않는다. 공용 책 표지와
프로필 이미지는 삭제 대상이 아니다. 이미 다운로드한 발췌 이미지나 외부 서비스가 복사한
내용, 다른 탭에 이미 표시된 화면까지 회수하는 기능은 아니다.

API 응답은 `private, no-store, max-age=0`이고 삭제 후 루트 layout을 재검증한다.
클라이언트는 새 문서로 이동해 현재 탭의 Router Cache와 메모리 검색 결과를 비운다.
기존 PWA 규칙은 HTML·RSC·API·Supabase 응답을 NetworkOnly로 취급한다.
기존 sessionStorage 생각 초안은 저장된 기록과 별개이며 이 삭제에서 일괄 제거하지 않는다.
삭제된 원본에 다시 저장하는 것은 DB 외래키와 권한 검사로 막힌다.

## 검증 범위

- `npm test`: 81개 파일, 545개 테스트 통과. 새 API 테스트 6개 포함.
- `node supabase/tests/run-book-deletion-contract.mjs`: 격리된 합성 PostgreSQL에서
  본인/친구 권한, 공개·비공개 기록과 연결 데이터 cascade, 실패 전체 롤백,
  대표 문장·책갈피 해제, 공유 링크 조회 차단, 공용 책·친구 기록 유지,
  빈 책 삭제, 삭제 재시도·재등록 보존 확인.
- Chromium 합성 미리보기: 390px 모바일 라이트·다크와 1280px 데스크톱 라이트,
  긴 제목, 기록 없는 상태, 취소 초기 포커스·Tab 순환·Esc·포커스 복귀,
  요청 대기·실패·재시도·성공 후 책장 이동. API 응답은 브라우저에서 모의 처리.
- 실제 로그인 계정의 삭제, 운영 DB 삭제, iOS 설치형 PWA·VoiceOver·실기기는 미검증.

- TypeScript 검사, lint(오류 0, 기존 경고 4), 프로덕션 빌드 통과. 빌드는 실제 비밀값 대신
  테스트용 Supabase URL/key를 사용했으며, 실제 서버 연결 검증을 의미하지 않는다.

## 2026-10-13 관리 메뉴 위치 검토

독립된 디자인 리뷰와 접근성·상호작용 리뷰를 반영했다. 읽기 상태 아래에 노출하던 삭제
버튼을 없애고, 본인 책 상세의 뒤로 가기와 같은 헤더 오른쪽에 44×44px 더보기 버튼을 둔다.
친구 상세와 공용 본문 컴포넌트에는 관리 메뉴를 넣지 않는다.

| Before | After | 이유 |
| --- | --- | --- |
| 책 정보 아래 단독 삭제 버튼 | 상단 오른쪽 더보기 메뉴 | 서지 정보와 책 관리 행동을 분리 |
| 메뉴 항목이 사라질 때 포커스 유실 가능 | 메뉴를 닫고 지속되는 트리거에 포커스를 둔 후 확인창 열기 | 취소 후 더보기로 복귀 |

Headless UI Menu의 키보드 의미론을 사용하고 메뉴 자체는 본문을 잠그지 않는다.
확인창은 메뉴 밖에 유지한다. 삭제 API와 확인 문구·오류 처리는 기존과 같다.

- Chromium 합성 데이터: 390px 라이트/다크, 320px 다크 오버플로 없음, 1280px 라이트 캡처.
- 방향키·Space로 메뉴 열기, Enter로 삭제 확인창 진입, 취소 초기 포커스,
  Esc/취소 후 더보기 포커스 복귀, 메뉴 밖 클릭 닫기, 모의 500 오류 흐름 확인.
- 변경 파일 TypeScript/lint 및 기존 삭제 API 6개 테스트 통과.
- Impeccable 탐지기는 실제 실행했으나 엔진 0.1.5가 없어 종료 코드 127로 실패했다.
  자동 탐지 통과로 간주하지 않는다. 두 리뷰는 독립적으로 소스와 가용 화면을 검토했고,
  최종 브라우저 검증은 주 작업에서 수행했다. 실기기는 미검증이다.
- Questions skipped: 사용자가 상단 더보기 위치와 병렬 검토를 이미 승인했다.
