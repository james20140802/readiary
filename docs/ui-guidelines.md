# Readiary UI Guidelines — 일기장과 간지

디자인 시스템 규범의 원본. 설계: [일기장과 간지 설계](superpowers/specs/2026-10-20-diary-vellum-redesign-design.md) 2절, 시안: [2026-10 HTML 시안](design/concept-2026-10/README.md). 한 장 요약은 루트의 [DESIGN.md](../DESIGN.md)다.
원칙: **문장이 주인공. 책의 목소리는 부리, 나의 도구는 산세리프. 깊이는 간지에만, 나머지는 헤어라인. 파랑은 잉크처럼 아껴서.**

새 디자인은 `redesign` 브랜치에서 화면을 하나씩 옮기며 쌓는다. 아직 옮기지 않은 화면은 새 토큰 위에서 옛 모양으로 그려지며, 그런 화면 전용 규칙은 아래 "옛 화면 규칙"에 남겨 두었다.

- 책장의 미선택 필터·보기 방식·정렬은 기본 `ink-sub`, 호버 `ink`다. 선택된 항목은 `ink`와 파란 밑줄로 구분한다. ‘기록 →’는 기본 `ink-sub`, 호버 `accent`를 사용한다.
- 불투명한 `ink-sub`와 `ink-faint`의 대비는 실제 배경 조합으로 확인한다. 투명도나 배경을 바꾸면 조합을 다시 검증한다.
- 원색 Tailwind 팔레트(`blue-500`, `red-500` 등)와 하드코딩 hex 금지.

## 서체 (Typography)

2서체 체계. **책의 목소리는 부리, 나의 도구는 산세리프.**

- `font-serif` — 마루 부리(셀프호스팅, `app/fonts.ts`). 인용문, 책 제목, 워드마크, 회고 카피.
- `font-sans` — Pretendard. UI 크롬, 버튼, 라벨, 메타데이터. (기본값)

크기는 시안의 큰 글자를 기준으로 한다. 아래 px는 루트 16px 기준이며 공용 토큰은 rem으로 `tailwind.config.js`의 `fontSize`에 정의한다.

| 역할 | 토큰 | 크기 / 줄 높이 / 굵기 |
| --- | --- | --- |
| 큰 제목 | `text-page-title` | 34px / 1.15 / 700 |
| 큰 제목(넓은 화면) | `text-page-title-lg` | 40px / 1.15 / 700 |
| 소제목 | `text-section-title` | 26px / 1.3 / 700 |
| 독립 문장 | `text-quote` | 25px / 1.6 / 600 |
| 큰 문장 | `text-quote-lg` | 30px / 1.55 / 600 |
| 생각 | `text-note` | 19px / 1.65 / 400 |
| 본문 | `text-body` | 17px / 1.6 / 400 |
| 짧은 보조 본문 | `text-body-sm` | 15px / 1.5 / 400 |
| 입력값 | `text-input` | 18px / 1.5 |
| 기본 버튼·탭·필터·정렬 | `text-button` | 17px / 1.25 / 600 |
| 작은 버튼·칩·행 안의 링크 | `text-button-sm` | 15px / 1.25 / 600 |
| 큰 버튼 | `text-button-lg` | 17px / 1.25 / 600 |
| 저자·날짜·진도·안내·오류(메타) | `text-caption` | 15px / 1.4 / 500 |
| 구분 라벨 | `text-overline` | 14px / 1.4 / 600 |
| 탭 바 이름 | `text-tab` | 12px / 1 / 600 |
| 아주 작은 안내 | `text-fine` | 13px / 1.5 / 500 |
| 날짜·상태 표식 | `text-seal` | 11px / 1rem / 700 |
| 비조작 장식 표식 | `text-ornament` | 12px / 1rem |

- Button sm/md/lg의 최소 높이는 40/48/48px이며 글자가 여러 줄이면 높이가 늘어난다. 버튼 글자는 토큰의 600 굵기를 쓰고 `font-bold`를 덧붙이지 않는다. variant는 크기와 독립적이다.
- `Input variant="line"`의 최소 높이는 48px, 글자는 `text-input`(18px)이다.
- 일반 UI는 역할 토큰을 사용한다. 같은 맥락과 역할 안에서는 크기를 통일한다.
- 랜딩의 큰 제목(`display-sm` 32px / `display` 48px), 장식용 인용부호(`quote-mark` 40px / `display-lg` 60px), 이니셜(`monogram` 36px)은 표현용 토큰이다.
- 발췌집의 고정 비율 내보내기 이미지와 OG 이미지의 픽셀 좌표계는 화면 조작 UI와 구분한다.
- 홈 기록 입력의 배치와 책 칩의 줄어드는 규칙, 책등의 별도 조판 크기는 "옛 화면 규칙"을 따른다.

## 바탕 (Background)

화면 뒤에는 일기장 괘선이 문서 전체 높이로 깔리고 본문이 그 위에 얹힌다. 괘선은 글과 함께 넘어간다(2026-10-29 사용자 피드백 — 종이가 멈춰 있고 글만 미끄러지는 것보다 공책을 넘기는 느낌). `body`가 기준 상자(`position: relative`)다. 구현은 `components/ui/RuledPaper.tsx`와 `app/globals.css`의 `.diary-ruled`이며 `AppShell`에 올라 있다.

- 괘선은 40px 간격의 `hairline` 가는 선이고, 격자는 문서 위에서 18px 내려서 시작한다.
- 여백선은 왼쪽 51px 자리의 1px `margin` 색 세로선이다. 괘선만 있는 변형은 `.diary-ruled--plain`, 데스크톱에서 사이드바 옆으로 비켜 앉는 변형은 `.diary-ruled--beside-sidebar`다(사이드바는 `components/shell/Sidebar.tsx`).
- 도구 화면(찾기·알림·설정 같은 곳)은 여백선 없이 괘선만 깐다. 여백선은 간지 틀을 쓰는 화면에만 있다.
- 여백선은 바탕의 무늬이지 본문의 왼쪽 경계가 아니다. 모바일에서는 입력칸도 날짜·간지와 같은 24px 여백에서 시작하고, 여백선 오른쪽으로 들여 쓰지 않는다(좁은 폭에서 칸이 줄고 좌우가 어긋나기 때문).
- 화면 틀은 `lib/shell/routes.ts`의 `frameFor(pathname)`이 경로로 정한다.
- 본문 `main`은 `relative`만 두고 `z-index`는 주지 않는다. DOM 순서상 괘선 뒤에 오므로 위에 그려지고, 스태킹 컨텍스트를 만들지 않아 본문 안의 고정 오버레이(내보내기 창·확인 창)가 탭 바·상단 바 위로 뜬다.

| 틀 | 경로 | 바탕 (`ruledFor`) |
| --- | --- | --- |
| `landing` | `/` | 없음. 랜딩이 자체 종이를 쓴다 |
| `bare` | 인증 절차·공개 링크·약관(`/login`, `/signup`, `/onboarding`, `/auth`, `/reset-password`, `/update-password`, `/share`, `/invite`, `/privacy`, `/terms`, `/email`) | 괘선만 |
| `leaves` | 오늘·나(`LEAVES_ROUTES`), 책장·책 한 권(`LEAVES_EXACT`), 기록 한 장 | 괘선 + 여백선 |
| `feed` | 소셜 피드용으로 예약한 틀. 아직 쓰는 경로가 없다 | 괘선 + 여백선 |
| `plain` | 그 밖의 모든 화면 | 괘선만 |

## 표면 규칙 (Surfaces)

- **깊이는 간지에만.** 반투명 트레이싱지 재질(간지)에만 얕은 그림자와 약한 `backdrop-filter`를 허용하고, 일반 카드·도구·입력은 `shadow-*` 없이 헤어라인으로 위계를 만든다. 간지는 쌓여 있을 법한 것(회상, 덧붙인 생각 묶음, 발췌집, 달마다 간지, 책 한 권의 기록, 바텀 시트, 탭 바·상단 바의 스크롤 재질)에만 쓰며 강한 블러의 글라스모피즘으로 바꾸지 않는다. 간지 재질(`.vellum`)·`Pile`·`Sheet`와 화면 틀(상단 바·탭 바·사이드바·장 넘김)은 구현되어 있고, 화면은 이전 PR이 하나씩 옮긴다. 옮기기 전 화면은 옛 표현이 남아 있다.
- 일반 위계는 헤어라인 굵기·톤(`hairline` → `hairline-strong`)과 배경 단차(`paper` → `card` → `card-raised`)로 만든다.
- 곡률은 절제: 카드 `rounded-md`(6px), 알약형(버튼·칩) `rounded-full`. 큰 라운드(`rounded-2xl` 이상) 지양.
- 기울어진 도장 박스(스탬프)와 물건을 픽셀로 그린 소품 장식 금지. 날짜 표식은 `<Seal>` 컴포넌트. 한자 장식(讀 등)은 허용.
- 이모지 장식 지양.

### 기록과 이어 남긴 생각

원래 문장과 남긴 생각 아래에 날짜별 생각을 원고처럼 이어 놓는다. 원문의 공유 안내와 이어 남긴 생각 영역은 여백으로 나누고, 생각마다 카드를 둘러 반복하지 않는다. 문장은 `text-quote`, 생각은 `text-note`의 부리 서체로 읽고, 날짜·공개 범위·조작은 산세리프로 구분한다. 작성에는 밑줄 없는 `Textarea variant="line"`과 알약형 `Button`을 사용한다.

홈 최근 문장·다시 꺼낸 문장·월별 회고의 원문은 읽기 모달에서 연다. 생각 보기와 작성 행동은 엔트리 상세로 연결한다. 회상 카드의 작성 버튼은 책 정보 오른쪽, 공간이 부족하면 다음 줄 오른쪽에 배치한다. 상세의 작성 버튼도 오른쪽에 둔다. 원문의 날짜·쪽수는 상단에, 반응·공유·관리 행동은 원문과 이어 남긴 생각 사이에 둔다. 책 상세의 생각 요약도 상세로 연결한다. 화면별 행동·공개 범위·초안 보호는 [이어 남긴 생각](features/entry-reflections.md)을 따른다.

## 간지 (Vellum)

반투명 트레이싱지 재질이다. 깊이(결·얕은 그림자·약한 `backdrop-filter`)는 간지에만 허용하고, 일반 카드와 도구는 헤어라인을 쓴다. 글라스모피즘(강한 blur 위주)으로 바꾸지 않는다.

- 쓰는 곳: 회상, 덧붙인 생각 묶음, 발췌집, 책 한 권의 기록 간지, 바텀 시트, 탭 바·상단 바·사이드바 재질.
- 값(불투명도·결·빛·그림자)의 원본은 `app/globals.css`의 `.vellum`(한 장)과 `.vellum-slip`(묶음의 한 장)이다. 문서에는 값을 복사하지 않는다.
- `prefers-reduced-transparency: reduce`에서는 불투명한 `rgb(var(--sheet))`로 바뀐다.

## 간지 묶음 (Pile)

`components/ui/Pile.tsx`는 간지를 옆으로 밀어 넘기는 묶음이다. 덧붙인 생각처럼 쌓여 있을 법한 기록에 쓴다.

- 사용: `items`, `getKey`, `renderSlip`, `label`을 넘긴다. `nextLabel`(예: '다음 생각')과 `getName`, `renderHeader`는 선택이다.
- 간지 폭은 묶음보다 `slipInset`(px)만큼 좁다. 비켜 쌓인 장이 들어갈 자리다. 기본은 52이고, 시안 값은 기록 화면 30, 토론 40, 발췌집 50이다.
- 간지 안 글은 시안대로 라벨 `text-fine font-semibold text-ink-sub`, 생각 부리 19px·줄 간격 1.55(데스크톱 21px)다. `text-note`의 줄 간격은 1.65라서, 화면을 옮길 때 간지 안에서는 줄 간격을 1.55로 맞춘다.
- 위치 표시(`2 / 5`)와 다음 버튼은 필수다. 밀기만으로 넘기게 두지 않는다.
- 움직임 값(시간·기울기·넘김 거리·간격)의 원본은 `lib/pile/geometry.ts`다.
- 키보드: 맨 위 간지의 요소와 다음 버튼만 포커스를 받는다. 아래 간지는 `inert`다.
- 움직임 줄이기: 이동 없이 순서만 바꾸고 160ms 동안 흐려진다.
- DOM 순서는 `items` 순서로 고정하고 쌓임은 `z-index`로만 표현한다. 넘기는 동안 노드를 옮기면 포커스와 읽기 순서가 끊기기 때문이다.

## 화면 틀 (Shell)

모든 앱 화면은 `components/AppShell.tsx`가 감싼다. 어떤 틀에 앉는지는 `lib/shell/routes.ts`의 `frameFor(pathname)`이 경로로 정하며, 틀 다섯 가지(`landing`·`bare`·`leaves`·`feed`·`plain`)와 각각의 바탕은 위 "바탕"의 표를 따른다. 내비(상단 바·탭 바·사이드바)는 로그인한 앱 화면에서만 보이고(`showsNav`), `bare`·`landing`에는 없다. 랜딩은 자체 메뉴(`components/landing/Landing.tsx`)를 쓴다.


- **상단 바**: 화면이 `useTopBar({ title?, brand?, back? })`로 작은 제목과 뒤로 가기를 정한다. 화면을 떠나면 브랜드 표시로 돌아간다. 오른쪽 동작 버튼은 설정값이 아니라 `TopBarActions` 컴포넌트를 자식으로 렌더해 포털로 꽂는다. 하나라도 있으면 기본 찾기·알림이 숨는다. 큰 제목은 `LargeTitle`을 쓰고, 이것이 화면 밖으로 나가면 바가 간지 재질과 작은 제목으로 바뀐다. 높이 52px, 큰 제목은 `text-page-title`(lg 이상 `text-page-title-lg`)다.
- **탭 바(모바일)와 사이드바(데스크톱)**: 크기·여백·재질 값의 원본은 `components/shell/TabBar.tsx`와 `Sidebar.tsx`다. 이 문서에 숫자를 따로 적지 않는다. 탭 이름은 **오늘·책장·소셜·나** 넷이며(`NAV_TABS`), 찾기와 알림은 상단 아이콘이다. 지금 화면이 어느 탭에 속하는지는 `tabFor(pathname)`이 정한다.
- **경계**: 1024px(`lg`) 아래는 탭 바, 이상은 사이드바다. 768–1023px(태블릿 세로 등)도 탭 바를 쓴다. 두 내비를 같은 화면에 함께 그리지 않는다.
- 새 내비 항목이나 경로 접두사를 더할 때는 `lib/shell/routes.ts`를 고치고 `routes` 테스트를 함께 갱신한다.

## 장 넘김 (Leaves)

모바일은 한 화면씩 끊기는 장 구조다. 모바일은 `Leaves` 안에 `Leaf`를 놓고, 데스크톱은 `DesktopLeaves` 안에 `DesktopLeaf`를 놓은 뒤 `LeafSwitch`로 구역을 건너뛴다. 둘은 `lg`에서 서로 바뀌어 보이므로 같은 내용을 양쪽에 둔다. 데스크톱 구역은 끊기지 않고 내용 높이대로 이어진다(2026-10-24 사용자 결정) — 화면 높이를 강제하면 트랙패드 관성과 부딪치고 내용이 적은 구역이 비어 보이기 때문이다. 데스크톱 구역은 빈 곳이 크게 남지 않도록 짧은 내용끼리 한 줄에 나란히 놓는다.

- **덮이면 연결된 것, 넘어가면 다음 것**: 앞 장 위에 얹히는 관계(문장과 그 위의 덧붙인 생각처럼)는 `LeafStack`으로 묶는다. 첫 장이 고정되고 뒤 장이 간지로 덮는다. 서로 독립된 다음 장은 묶지 않고 나란히 둔다. 앞 장이 그대로 위로 밀려 나간다.
- **간지 장**: 쌓여 있을 법한 장만 `vellum`을 준다. 내용이 긴 장은 `free`로 화면보다 길어도 되게 한다.
- **긴 장의 멈춤**: `free` 장은 머리와 바닥 두 곳에 멈춘다(`.leaf-end`). 그 사이는 장이 화면보다 커서 자유롭게 읽힌다. 바닥 멈춤이 없으면 끝 근처에서 다음 장 머리로 끌려가 끝을 보기 어렵다.
- **탭 이동은 맨 위에서**: 탭 바·사이드바로 다른 탭에 가면 새 화면 맨 위에서 시작하고, 지금 탭을 다시 누르면 맨 위로 올라간다(`components/shell/tabScroll.ts`). 뒤로 가기는 건드리지 않는다.
- **도구 화면은 장 넘김을 쓰지 않는다**: 찾기·알림·설정·폼은 `plain` 틀의 흐르는 화면이다. 끊기는 스크롤은 읽는 화면에만 쓴다.
- **스크롤 안내를 넣지 않는다**: 다음 장 머리를 탭 바 위에 걸쳐 보이기, 처음 한 번 살짝 올라오기 같은 힌트는 하지 않기로 했다.
- **화면 추가**: `lib/shell/routes.ts`의 `LEAVES_ROUTES`에 경로를 더하면 `frameFor`가 `leaves`를 돌려주고 여백선이 깔린다. 그 화면이 `Leaves`를 렌더해야 장 넘김이 켜진다(`html:has(.leaves)`).
- **높이**: 장 높이는 `--vh`다. `useStableViewportHeight`가 폭이 바뀔 때(회전·분할 화면)만 다시 재므로 주소창이 접히는 스크롤 중에는 장이 출렁이지 않는다.
- **움직임 줄이기**: 덮이는 장의 기울어져 내려앉기와 덮인 장의 가라앉기는 스크롤에 맞물린 효과라 `prefers-reduced-motion`에서는 끈다. 장은 여전히 한 장씩 넘어간다.
- **상단 바 연동**: `Leaves`가 보이는 장의 제목을 상단 바에 알리고, 첫 장이 아닐 때 바를 간지 재질로 바꾼다. 장마다 `title`을 준다.

## 바텀 시트 (Sheet)

`components/ui/Sheet.tsx`가 간지 재질의 시트다. 모바일은 아래에서 올라오고(손잡이 포함), lg 이상은 가운데 창이다.

- 사용: `open`, `onClose`를 넘기고, 머리줄이 필요하면 `title`(과 `closeLabel`, 기본 '닫기')을 준다. 제목이 없으면 손잡이와 몸만 그린다.
- 포커스 가두기·Esc·바깥 누르기는 Headless UI가, 들어오고 나가는 움직임은 framer가 맡는다(320ms `EASE_DRAWER`, 데스크톱 200ms `EASE_OUT`).
- 시트 위에 시트를 열어도 안전하다. `InertBackground`가 참조 횟수를 세므로 안쪽 시트가 닫혀도 바깥 시트 뒤의 배경은 계속 비활성으로 남는다.
- `Modal`은 이제 `Sheet`를 감싸 시트 모양으로 열린다.
- 기존 시트(`EntryEditSheet`, `CommentBottomSheet`, `LikersBottomSheet`, `WeeklyLetterSheet` 등)는 화면 이전 PR에서 옮긴다. 각 화면 이전 PR에서 `Sheet`로 바꾼다.

## 움직임 (Motion)

움직임은 장식이 아니라 변화를 이어 주는 도구다. 자주 쓰는 동작은 빠르고 조용하게, 한 권에 한 번뿐인 순간(완독 등)만 조금 천천히 한다.

- 곡선은 토큰만 쓴다. `--ease-out`(들어오고 나감, 기본) · `--ease-in-out`(화면 안 이동) · `--ease-drawer`(시트·서랍). Tailwind는 `ease-ink-out`·`ease-ink-in-out`·`ease-drawer`, framer는 `lib/motion.ts`의 `EASE_*`다. Tailwind 기본 `ease-out`/`ease-in`은 약해서 쓰지 않는다.
- 바닥 시트는 `Sheet`의 320ms `EASE_DRAWER`(스프링 아님)다. 화면 이전 전의 시트들은 아직 `SHEET_TRANSITION`(350ms)을 쓰며, 각 화면 PR에서 `Sheet`로 옮기며 사라진다.
- 눌림은 `Button`처럼 `scale(0.97)`·150ms로 조용히. 불투명도로 눌림을 표현하지 않는다.
- 좋아요를 켜는 순간에만 하트가 한 번 부풀었다 돌아온다(`.heart-pop`, 1.12배·220ms `--ease-out`). 끌 때와 처음부터 눌려 있던 하트는 움직이지 않고, 숫자는 그대로 둔다. 줄이는 모션에서는 색만 바뀐다.
- 지우거나 펼쳐서 아래 내용이 밀리는 곳은 높이째 접고 펼친다(`hooks/useFold`, 220ms `--ease-in-out`). 지운 댓글·처리한 친구 요청·책 상세에서 지운 기록이 접히며 빠지고, 홈의 덧붙이기 입력칸이 펼쳐진다. 목록에 원래 있던 항목과 새로 생긴 항목은 그 자리에 놓이고, 필터로 빠지는 항목은 바로 사라진다. 목록은 `components/ui/FoldList`(`FoldList`·`FoldDiv`·`FoldLi`)로 짠다. 마지막 항목도 접히도록 목록 상자는 비어도 남기고, 빈 문구는 그 항목이 다 접힌 뒤에 놓는다. 접히기 시작한 항목은 `inert`라 그 사이 눌리거나 포커스되지 않는다. 긴 문장의 '계속 읽기·접기'(`ClampedText`)도 같은 시간·곡선으로 높이가 늘고 준다. 줄이는 모션에서는 높이가 한 번에 바뀌고 흐려지고 나타나는 것만 남는다.
- `hover:` 스타일은 Tailwind `hoverOnlyWhenSupported`로 hover가 되는 기기에서만 적용된다. 터치 기기에서 눌림 말고는 hover에 기대지 않는다.
- 움직이는 속성은 `transform`과 `opacity`다. 크기·위치로 바뀌는 곳은 `transition-all` 대신 속성을 지정한다.
- 감축 모션: framer는 앱 루트의 `MotionProvider`(`reducedMotion="user"`)가 이동을 빼고 opacity만 남긴다. CSS 키프레임은 `prefers-reduced-motion`에서 이동을 빼고 나타남만 남긴다. 컴포넌트에서 `MotionConfig`를 따로 두지 않는다.

## 입력 포커스와 작은 조작 영역 (2026-09-30)

[Figma 확정 시안](https://www.figma.com/design/wkPwRJbx2dyzoXcthh1iPk?node-id=4-251)을 따른다. 긴 기록은 A안(왼쪽 여백 표시), 짧은 입력은 파란 잉크색만 바꾸는 밑줄이다. 로그인 입력에 두 번째 선·외곽 링·굵어진 밑줄을 추가하지 않는다. 오류가 있는 짧은 입력은 danger 밑줄을 유지한다. 색은 기존 accent 토큰(라이트 #2D5FB8, 다크 #85A9EC)을 사용한다.

비밀번호 표시, 프로필 이미지 삭제는 아이콘 크기를 유지하면서 클릭 영역을 44×44px로 확보한다. 기록의 쪽수 입력은 44×44px, 날짜는 최소 높이 44px로 만든다. 키보드로 버튼에 접근하면 accent 포커스 링을 표시한다.

레이블이 있는 공용 `Textarea variant="line"`의 여백 표시는 레이블 높이의 세로 중앙에 맞춘다. 레이블 크기는 기존 `text-caption`을 유지한다.

빠른 기록의 첫 입력과 랜딩의 같은 체험 입력은 입력 영역이 하나이므로 밑줄·파란 여백 표시 없이 커서만 보여준다. 저장 뒤 덧붙이기와 문장·생각이 나뉜 기록 작성·수정에는 여백 표시를 유지한다.


## 옛 화면 규칙 (화면 이전 중)

아직 새 디자인으로 옮기지 않은 화면에만 적용되는 규칙이다. 해당 화면 PR에서 새 규칙으로 바꾸거나 지운다. 3D 책·엽서는 2026-10-27에 걷어 냈다. 남은 쪽지의 깊이 표현은 새 화면에 확대하지 않는다.

### 홈 기록 입력과 책 선택

홈 기록 입력 크기는 기존 값을 유지한다. 하단은 넓으면 책 최대 3권·내 책·조작부를 한 줄에 놓고, 공간이 부족하면 책 선택과 조작부를 각각 한 줄로 나눈다. 책 선택 한 줄에도 부족하면 실제 너비에 따라 3→2→1권으로 줄이며 선택한 책과 내 책은 남긴다. 책 칩은 스크롤하거나 줄바꿈하지 않고, 문장·생각·비공개·남기기는 항상 한 줄을 유지한다.

### 책등 조판

책등은 책의 비례에 종속된 별도 조판이다. 책등 글자 12px를 유지한다. 이 내부의 작은 크기는 명시적 예외이며 일반 UI로 확대 적용하지 않는다. 활자를 키우기 위해 책 높이를 늘리지 않는다.

### 끼움 쪽지 미리보기

책 상세와 기록 읽기 모달은 이어 남긴 생각이 있을 때만 최신 생각 최대 세 줄을 종이 표면과 종이 안의 날짜로 보여준다. 쪽지 전체는 엔트리 상세의 생각 영역으로 연결된다. 본문과 생각 행동 사이에는 가로선을 두지 않는다. 생각이 없거나 개수가 확인되지 않았으면 보기 링크를 만들지 않는다. 작성 행동은 오른쪽에 둔다. 읽기 모달은 보기·작성·파란 자세히 링크를 같은 행동 행에 두고 공간이 부족할 때만 줄바꿈한다. 상세의 생각 목록은 종이 카드를 반복하지 않고 날짜와 원고 흐름을 사용한다.

끼움 쪽지의 목록 미리보기는 작은 테이프와 접힌 하단 모서리로 종이를 표현하고 날짜는 종이 안에 둔다. 책 상세의 작성 링크는 쪽지 밖에서 원문 수정 바로 왼쪽에 같은 줄로 배치한다. 좁은 폭에서는 반응 영역과 행동 그룹을 줄바꿈할 수 있지만 작성·수정 그룹은 함께 유지한다.

쪽지는 최대 18rem 폭으로 제한하고 원문에서 살짝 들여써 짧은 메모지 비율을 만든다. 높이는 내용에 맞추며 고정 비율이나 최소 높이로 빈 종이를 늘리지 않는다. 테이프와 접힌 모서리는 함께 유지한다. 생각이 두 개 이상이면 뒤쪽 종이 한 장을 살짝 드러내 쌓인 기록을 표현하며, 한 개일 때는 겹침 장식을 표시하지 않는다. 상세에서는 날짜를 배경 없는 추신처럼 표시하고 그 아래에 생각을 이어 읽는다.

### 한 주의 독서 편지

주간 타임라인의 이미지 내보내기는 화면 안에서 기록 선택 → 편지 생성 → 이미지 미리보기·저장으로 이어진다. 조작은 기존 산세리프와 `Button`, 선택은 라벨이 연결된 체크박스를 사용한다. 비공개 기록과 생각 포함 여부는 생성 전에 확인할 수 있어야 한다.

내보낸 편지는 기존 이미지 공유의 `lib/share/palette.ts` 밝은 팔레트를 사용한다. 540 × 760 조판을 2배율 PNG로 저장하며, 제목·책 이름·문장·생각은 부리, 날짜·종류·장 번호는 산세리프로 구분한다. 긴 내용은 글자를 줄이거나 자르지 않고 실제 높이를 측정해 다음 장으로 이어 놓는다. 이는 내보내기 파일의 조판이며 일반 앱 화면의 크기 토큰을 바꾸지 않는다. 동작·공개 범위·검증 한계는 [주간 타임라인 검증 기록](qa/2026-09-24-weekly-timeline.md)을 따른다.

주간 타임라인의 월·일은 왼쪽 마진에 두고, 전체 날짜는 보조기술에 제공한다. 독서 편지 PNG는 두 줄 제목과 기간을 나란히 놓고 하단에 이어지는 장 또는 마지막 장에 맞는 맺음말을 둔다. 본문은 기존 측정·분할 영역을 유지한다.

편지 저장은 미리보기 위의 `편지 전체 저장` 한 번으로 제공한다. 한 장은 PNG, 여러 장은 PNG를 묶은 ZIP으로 저장하고 형식을 버튼 근처에 안내한다. 장마다 저장 버튼을 반복하지 않는다.

#### 2026-09-26 공유창 우선 저장

완성된 PNG 전체를 `navigator.canShare({ files })`로 검사하고 지원하면 `이미지 저장 · 공유` 버튼 하나로 OS 공유창에 전달한다. 이 경우 ZIP을 만들지 않는다. 미지원 환경에서만 기존 PNG/ZIP 다운로드를 제공한다. 공유 취소는 오류 없이 재시도 가능하고, 공유창 열기 성공을 사진 저장 완료로 표시하지 않는다. Android의 저장 대상과 메뉴는 설치된 앱에 따라 달라 동일한 사진 저장 메뉴를 보장하지 않는다.

검증: 475개 테스트·TypeScript·변경 파일 ESLint 통과. Chromium에서 파일 공유 API를 모의하여 두 PNG 전달, 다운로드 버튼 없음, 취소 후 재시도를 확인했다. 이 검증은 실제 iOS/Android 공유창·갤러리 저장을 검증한 것이 아니다. 이번 변경 후 production build는 재실행하지 않았다.
