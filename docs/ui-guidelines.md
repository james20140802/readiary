# Readiary UI Guidelines — 먹과 종이

에디토리얼 디자인 시스템 규범. 시안: "먹과 종이" 아티팩트, 스펙 §6.
원칙: **문장이 주인공. 콘텐츠는 부리, 도구는 산세리프. 그림자 대신 헤어라인. 파랑은 잉크처럼 아껴서.**

## 색 (Colors)

모든 색은 `app/globals.css`의 CSS 변수를 Tailwind 토큰이 참조한다.
**라이트/다크는 변수가 자동 전환하므로 색상에 `dark:` 프리픽스를 쓰지 않는다.**

- 책장의 미선택 필터·보기 방식·정렬은 기본 `ink-sub`, 호버 `ink`다. 선택된 항목은 `ink`와 파란 밑줄로 구분한다. ‘기록 →’는 기본 `ink-sub`, 호버 `accent`를 사용한다.
- 현재 불투명한 `ink-sub`의 대비는 paper/card/card-raised 순서로 라이트 5.11/5.46/4.80:1, 다크 5.66/5.19/4.63:1이다. 투명도나 배경을 바꾸면 실제 조합을 다시 검증한다.
- 원색 Tailwind 팔레트(`blue-500`, `red-500` 등)와 하드코딩 hex 금지.

## 서체 (Typography)

2서체 체계. **책의 목소리는 부리, 나의 도구는 산세리프.**

- `font-serif` — 마루 부리(셀프호스팅, `app/fonts.ts`). 인용문, 책 제목, 워드마크, 회고 카피.
- `font-sans` — Pretendard. UI 크롬, 버튼, 라벨, 메타데이터. (기본값)

크기는 같은 맥락과 역할 안에서 통일한다. 화면 전체의 활자를 일괄 확대하지 않는다. 아래 px는 루트 16px 기준이며 공용 토큰은 rem으로 정의한다.

| 역할 | 토큰 | 크기 / 줄 높이 |
| --- | --- | --- |
| 페이지 제목 | `text-page-title` | 24 / 32px |
| 섹션 제목 | `text-section-title` | 18 / 28px |
| 독립 인용 | `text-quote` | 20px / 1.85 |
| 본문·생각 | `text-body`, `text-note` | 15px / 1.75 |
| 입력값 | `text-input` | 16 / 24px |
| 기본 버튼·탭·필터·정렬 | `text-button` | 14 / 20px |
| 작은 버튼·칩·행 안의 링크 | `text-button-sm` | 13 / 20px |
| 큰 버튼 | `text-button-lg` | 16 / 24px |
| 저자·날짜·진도·안내·오류 | `text-caption` | 13 / 20px |
| 짧은 보조 본문 | `text-body-sm` | 14 / 22px |
| 구분 라벨 | `text-overline` | 12 / 16px |
| 날짜·상태 표식 | `text-seal` | 11 / 16px |
| 비조작 장식 표식 | `text-ornament` | 12 / 16px |

- Button sm/md/lg의 최소 높이는 32/40/48px이며 글자가 여러 줄이면 높이가 늘어난다. 글자 크기와 클릭 영역은 구분한다. variant는 크기와 독립적이다.
- 홈 기록 입력 크기는 기존 값을 유지한다. 하단은 넓으면 책 최대 3권·내 책·조작부를 한 줄에 놓고, 공간이 부족하면 책 선택과 조작부를 각각 한 줄로 나눈다. 책 선택 한 줄에도 부족하면 실제 너비에 따라 3→2→1권으로 줄이며 선택한 책과 내 책은 남긴다. 책 칩은 스크롤하거나 줄바꿈하지 않고, 문장·생각·비공개·남기기는 항상 한 줄을 유지한다.
- 일반 UI는 역할 토큰을 사용한다. 책장 목록은 기존 제목·저자·진도의 크기와 행 배치를 유지하고 필터·정렬만 14px로 맞춘다. 작은 조작 문구는 `ink-sub` 대비를 먼저 확보한다.
- 책등·펼친 책·프로필 책은 책의 비례에 종속된 별도 조판이다. 원래 책등 12px, 펼친 책 10:7 비율, 프로필 표지 300×430px와 인덱스 92×20px를 유지한다. 이 내부의 기존 10–18px 및 반 단계 크기는 명시적 예외이며 일반 UI로 확대 적용하지 않는다.
- 프로필 책은 좁은 화면에서 비율을 유지해 축소한다. 펼친 책의 긴 정보는 내부 스크롤, 조작 링크는 줄바꿈으로 수용한다. 활자를 키우기 위해 책 높이를 늘리지 않는다.
- 랜딩의 큰 제목(`display-sm` 32px / `display` 48px), 장식용 인용부호(`quote-mark` 40px / `display-lg` 60px), 이니셜(`monogram` 36px)은 표현용 토큰이다.
- 발췌집의 고정 비율 내보내기 이미지와 OG 이미지의 픽셀 좌표계는 화면 조작 UI와 구분한다.

## 표면 규칙 (Surfaces)

- **그림자 금지.** `shadow-*` 클래스를 쓰지 않는다. 위계는 헤어라인 굵기·톤(`hairline` → `hairline-strong`)과 배경 단차(`paper` → `card` → `card-raised`)로.
- 곡률은 절제: 카드 `rounded-md`(6px), 알약형(버튼·칩) `rounded-full`. 큰 라운드(`rounded-2xl` 이상) 지양.
- 기울어진 도장 박스(스탬프) 장식 금지. 날짜 표식은 `<Seal>` 컴포넌트. 한자 장식(讀 등)은 허용.
- 이모지 장식 지양.

| 컴포넌트 | 요지 |
| --- | --- |

### 기록과 이어 남긴 생각

원래 문장과 남긴 생각 아래에 날짜별 생각을 원고처럼 이어 놓는다. 원문의 공유 안내와 이어 남긴 생각 영역은 여백으로 나누고, 생각마다 카드를 둘러 반복하지 않는다. 문장은 `text-quote`, 생각은 `text-note`의 부리 서체로 읽고, 날짜·공개 범위·조작은 산세리프로 구분한다. 작성에는 밑줄 없는 `Textarea variant="line"`과 알약형 `Button`을 사용한다.

홈 최근 문장·다시 꺼낸 문장·월별 회고의 원문은 읽기 모달에서 연다. 생각 보기와 작성 행동은 엔트리 상세로 연결한다. 회상 카드의 작성 버튼은 책 정보 오른쪽, 공간이 부족하면 다음 줄 오른쪽에 배치한다. 상세의 작성 버튼도 오른쪽에 둔다. 원문의 날짜·쪽수는 상단에, 반응·공유·관리 행동은 원문과 이어 남긴 생각 사이에 둔다. 책 상세의 생각 요약도 상세로 연결하고, 친구 엽서는 기존 앞뒷면을 유지하며 생각 개수를 누르면 엔트리 상세로 이동한다. 화면별 행동·공개 범위·초안 보호는 [이어 남긴 생각](features/entry-reflections.md)을 따른다.

## 움직임 (Motion)

움직임은 장식이 아니라 변화를 이어 주는 도구다. 자주 쓰는 동작은 빠르고 조용하게, 한 권에 한 번뿐인 순간(완독 등)만 조금 천천히 한다.

- 곡선은 토큰만 쓴다. `--ease-out`(들어오고 나감, 기본) · `--ease-in-out`(화면 안 이동) · `--ease-drawer`(시트·서랍). Tailwind는 `ease-ink-out`·`ease-ink-in-out`·`ease-drawer`, framer는 `lib/motion.ts`의 `EASE_*`다. Tailwind 기본 `ease-out`/`ease-in`은 약해서 쓰지 않는다.
- 책장 넘김 3D 동작만 `EASE_PAGE`(`[0.4, 0, 0.2, 1]`, CSS는 `--ease-page`·Tailwind `ease-page`)를 쓴다.
- 바닥 시트는 `SHEET_TRANSITION`(350ms, 스프링 아님).
- 목록이 처음 그려질 때는 `.ink-in`(320ms, 6px 떠오름)으로 차례 등장한다. 순번은 `lib/motion.ts`의 `inkIn(i)`로 주고 간격은 40ms, 여섯 번째부터는 함께 나타난다. 다시 그려지거나 정렬만 바뀔 때는 움직이지 않는다. 끝난 뒤 transform이 남지 않게 `backwards`를 쓰지만, 등장하는 동안에는 조상의 transform·opacity가 `fixed` 자손을 가두므로 항목 안에서 여는 시트는 `components/ui/BodyPortal`로 body에 띄운다.
- 책 상세의 기록 사이 헤어라인은 `.rule-draw`로 같은 순번(`inkIn(i)`)에 맞춰 왼쪽에서부터 그어진다(640ms `--ease-in-out`, 항목보다 120ms 늦게 시작, `finish-rule` 키프레임). 선은 옅은 헤어라인이라 `--ease-out`으로는 첫 0.1초에 거의 다 그어져 보이지 않는다. 선은 항목마다 늘 렌더하고 첫 줄만 감춰 정렬·필터로 다시 그어지지 않게 한다. 줄이는 모션에서는 나타남만 남긴다.
- 눌림은 `Button`처럼 `scale(0.97)`·150ms로 조용히. 불투명도로 눌림을 표현하지 않는다.
- `hover:` 스타일은 Tailwind `hoverOnlyWhenSupported`로 hover가 되는 기기에서만 적용된다. 터치 기기에서 눌림 말고는 hover에 기대지 않는다.
- 움직이는 속성은 `transform`과 `opacity`다. 크기·위치로 바뀌는 곳은 `transition-all` 대신 속성을 지정한다.
- 감축 모션: framer는 앱 루트의 `MotionProvider`(`reducedMotion="user"`)가 이동을 빼고 opacity만 남긴다. CSS 키프레임은 `prefers-reduced-motion`에서 이동을 빼고 나타남만 남긴다.

## 다크 모드

어두운 종이. OS 설정 따름(`darkMode: 'media'`), 앱 내 토글 없음.
토큰이 자동 전환하므로 **컴포넌트 코드에는 다크 분기가 없어야 정상**이다. `dark:`가 필요하다고 느껴지면 토큰 선택이 잘못된 것.

### 끼움 쪽지 미리보기

책 상세와 기록 읽기 모달은 이어 남긴 생각이 있을 때만 최신 생각 최대 세 줄을 종이 표면과 종이 안의 날짜로 보여준다. 쪽지 전체는 엔트리 상세의 생각 영역으로 연결된다. 본문과 생각 행동 사이에는 가로선을 두지 않는다. 생각이 없거나 개수가 확인되지 않았으면 보기 링크를 만들지 않는다. 작성 행동은 오른쪽에 둔다. 읽기 모달은 보기·작성·파란 자세히 링크를 같은 행동 행에 두고 공간이 부족할 때만 줄바꿈한다. 친구 엽서는 기존 간결한 개수 링크를 유지한다. 상세의 생각 목록은 종이 카드를 반복하지 않고 날짜와 원고 흐름을 사용한다.

끼움 쪽지의 목록 미리보기는 작은 테이프와 접힌 하단 모서리로 종이를 표현하고 날짜는 종이 안에 둔다. 책 상세의 작성 링크는 쪽지 밖에서 원문 수정 바로 왼쪽에 같은 줄로 배치한다. 좁은 폭에서는 반응 영역과 행동 그룹을 줄바꿈할 수 있지만 작성·수정 그룹은 함께 유지한다.

쪽지는 최대 18rem 폭으로 제한하고 원문에서 살짝 들여써 짧은 메모지 비율을 만든다. 높이는 내용에 맞추며 고정 비율이나 최소 높이로 빈 종이를 늘리지 않는다. 테이프와 접힌 모서리는 함께 유지한다. 생각이 두 개 이상이면 뒤쪽 종이 한 장을 살짝 드러내 쌓인 기록을 표현하며, 한 개일 때는 겹침 장식을 표시하지 않는다. 상세에서는 날짜를 배경 없는 추신처럼 표시하고 그 아래에 생각을 이어 읽는다.

## 한 주의 독서 편지

주간 타임라인의 이미지 내보내기는 화면 안에서 기록 선택 → 편지 생성 → 이미지 미리보기·저장으로 이어진다. 조작은 기존 산세리프와 `Button`, 선택은 라벨이 연결된 체크박스를 사용한다. 비공개 기록과 생각 포함 여부는 생성 전에 확인할 수 있어야 한다.

내보낸 편지는 기존 이미지 공유의 `lib/share/palette.ts` 밝은 팔레트를 사용한다. 540 × 760 조판을 2배율 PNG로 저장하며, 제목·책 이름·문장·생각은 부리, 날짜·종류·장 번호는 산세리프로 구분한다. 긴 내용은 글자를 줄이거나 자르지 않고 실제 높이를 측정해 다음 장으로 이어 놓는다. 이는 내보내기 파일의 조판이며 일반 앱 화면의 크기 토큰을 바꾸지 않는다. 동작·공개 범위·검증 한계는 [주간 타임라인 검증 기록](qa/2026-09-24-weekly-timeline.md)을 따른다.

주간 타임라인의 월·일은 왼쪽 마진에 두고, 전체 날짜는 보조기술에 제공한다. 독서 편지 PNG는 두 줄 제목과 기간을 나란히 놓고 하단에 이어지는 장 또는 마지막 장에 맞는 맺음말을 둔다. 본문은 기존 측정·분할 영역을 유지한다.

편지 저장은 미리보기 위의 `편지 전체 저장` 한 번으로 제공한다. 한 장은 PNG, 여러 장은 PNG를 묶은 ZIP으로 저장하고 형식을 버튼 근처에 안내한다. 장마다 저장 버튼을 반복하지 않는다.

### 2026-09-26 공유창 우선 저장

완성된 PNG 전체를 `navigator.canShare({ files })`로 검사하고 지원하면 `이미지 저장 · 공유` 버튼 하나로 OS 공유창에 전달한다. 이 경우 ZIP을 만들지 않는다. 미지원 환경에서만 기존 PNG/ZIP 다운로드를 제공한다. 공유 취소는 오류 없이 재시도 가능하고, 공유창 열기 성공을 사진 저장 완료로 표시하지 않는다. Android의 저장 대상과 메뉴는 설치된 앱에 따라 달라 동일한 사진 저장 메뉴를 보장하지 않는다.

검증: 475개 테스트·TypeScript·변경 파일 ESLint 통과. Chromium에서 파일 공유 API를 모의하여 두 PNG 전달, 다운로드 버튼 없음, 취소 후 재시도를 확인했다. 이 검증은 실제 iOS/Android 공유창·갤러리 저장을 검증한 것이 아니다. 이번 변경 후 production build는 재실행하지 않았다.

### 입력 포커스와 작은 조작 영역 (2026-09-30)

[Figma 확정 시안](https://www.figma.com/design/wkPwRJbx2dyzoXcthh1iPk?node-id=4-251)을 따른다. 긴 기록은 A안(왼쪽 여백 표시), 짧은 입력은 파란 잉크색만 바꾸는 밑줄이다. 로그인 입력에 두 번째 선·외곽 링·굵어진 밑줄을 추가하지 않는다. 오류가 있는 짧은 입력은 danger 밑줄을 유지한다. 색은 기존 accent 토큰(라이트 #2D5FB8, 다크 #85A9EC)을 사용한다.

비밀번호 표시, 프로필 이미지 삭제는 아이콘 크기를 유지하면서 클릭 영역을 44×44px로 확보한다. 기록의 쪽수 입력은 44×44px, 날짜는 최소 높이 44px로 만든다. 키보드로 버튼에 접근하면 accent 포커스 링을 표시한다.

레이블이 있는 공용 `Textarea variant="line"`의 여백 표시는 레이블 높이의 세로 중앙에 맞춘다. 레이블 크기는 기존 `text-caption`을 유지한다.

빠른 기록의 첫 입력과 랜딩의 같은 체험 입력은 입력 영역이 하나이므로 밑줄·파란 여백 표시 없이 커서만 보여준다. 저장 뒤 덧붙이기와 문장·생각이 나뉜 기록 작성·수정에는 여백 표시를 유지한다.
