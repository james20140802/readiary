# 일기장과 간지 — 새 디자인 전환 설계

- 작성: 2026-10-20
- 상태: 사용자 검토 대기
- 근거 시안: [`docs/design/concept-2026-10/`](../../design/concept-2026-10/README.md) (PR #135)
- 근거 결정: Notion 결정 로그 2026-10-06~18, 문서 "2026-10 디자인 재검토 — 일기장과 간지 HTML 시안"

## 0. 목적과 범위

2026-10 디자인 재검토에서 확정한 시안을 실제 앱에 옮긴다. 기준은 **시안과 같은 느낌**이다. 값·곡선·시간·자리는 시안에서 그대로 가져오고, 바꿔야 할 때는 이 문서에 이유를 남긴다.

포함한다.

- 주소에서 `/protected` 접두사를 뺀다(1절, 먼저 `main`으로).
- 시각 체계와 토대 부품(2절).
- 모든 화면을 시안 문법으로 옮긴다(3절).
- 새 기능 셋: 책 플래그, 원고지 필사, 달마다 간지(4절).
- 랜딩 재작성.

포함하지 않는다.

- **문장 토론.** 새 테이블·RLS·알림이 필요해 새 디자인 배포 후 별도 스펙으로 이어 붙인다. 그동안 소셜 탭은 기존 "친구의 문장"을 새 디자인으로 보여 준다.
- 앱 안의 옛·새 화면 전환 스위치. 두지 않는다(5절).
- 머문 시간 측정 등 새 개인정보 수집.

## 1. 주소 정리 — `/protected` 빼기 (먼저, `main`으로)

화면 모양과 무관한 변경이라 새 디자인과 분리해 먼저 머지한다. 파일을 통째로 옮기므로 `redesign` 브랜치를 만들기 전에 끝내야 충돌이 적다.

| 지금                             | 바뀐 뒤                                                      |
| -------------------------------- | ------------------------------------------------------------ |
| `/protected/dashboard`           | `/today`                                                     |
| `/protected/books/…`             | `/books/…`                                                   |
| `/protected/entry/…`             | `/entry/…`                                                   |
| `/protected/profile/…`           | `/profile/…`                                                 |
| `/protected/social/…`            | `/social/…`                                                  |
| `/protected/search`              | `/search`                                                    |
| `/protected/notifications/…`     | `/notifications/…`                                           |

- 폴더: `app/protected/*` → 라우트 그룹 `app/(app)/*`. 그룹 이름은 주소에 나타나지 않고 공통 `layout.tsx`(ReflectionFeatureProvider)는 유지된다. `dashboard` 폴더는 `today`로 바꾼다.
- 로그인 검사: `proxy.ts`의 `startsWith('/protected')` 검사를 **로그인이 필요한 주소 목록 상수** 하나로 바꾼다. 목록은 `/today`, `/books`, `/entry`, `/profile`, `/settings`, `/social`, `/search`, `/notifications`, `/pilsa`. 경계는 정확히 비교한다(`/books`와 `/books/…`는 포함, `/bookstore` 같은 우연한 접두사는 제외). `matcher`도 같은 목록을 따른다. 로그인 후 돌아갈 `redirect` 파라미터 처리는 그대로다. 데이터 접근 제한(RLS)과 서버 인증(`getServerUser`)은 주소와 무관하게 그대로 동작한다.
- **옛 주소 영구 이동(308):** `/protected/dashboard` → `/today`, `/protected/:path*` → `/:path*`. 이미 설치된 PWA, 보낸 알림·이메일 링크, 북마크, DB에 저장된 푸시 주소가 깨지지 않는다. 이 이동은 새 디자인 배포 뒤에도 남겨 둔다.
- 함께 바꾸는 것: 앱 안 링크 약 70곳(`app`·`components`·`lib`·`hooks`·`proxy.ts`), `lib/auth/safeRedirect.ts`의 기본 주소, 서비스 워커(`worker/index.js`)의 알림 클릭 주소, 푸시 리마인더 DB 함수의 `href`(새 마이그레이션으로 함수 재정의), 테스트의 주소 기대값. Supabase 대시보드의 이메일 템플릿·리다이렉트 허용 목록에 `/protected` 주소가 있으면 사람 작업으로 바꾼다(308 이동이 있어 늦어도 깨지지는 않는다).
- 검증: 로그인 안 한 상태로 각 주소 → 로그인 화면(돌아갈 주소 유지), 로그인 상태로 옛 주소 → 새 주소, 설치형 PWA 재실행, 알림 링크 열기. `npm test`·`lint`·`build`.

## 2. 시각 체계와 토대

### 2.1 색

토큰 **이름은 유지**하고 값만 시안으로 바꾼다. 일반 컴포넌트에서 `dark:` 분기를 쓰지 않는 원칙도 유지한다.

| 토큰          | 라이트 지금 → 바뀜      | 다크                                        |
| ------------- | ----------------------- | ------------------------------------------- |
| `paper`       | `#F7F3EC` → `#F4F0E8`   | `#1B1612` → `#1A1714`                       |
| `ink`         | `#221E1A` 유지          | `#EAE2D6` → `#ECE5DA`                       |
| `ink-sub`     | `#6E665C` → `#6B645A`   | `#9A8F81` → `#B1A899`                       |
| `ink-faint`   | `#A39A8D` → `#9E968A`   | **`#8E8476` 유지**(작은 글자 4.5:1 대비)    |
| `hairline`    | `#E3DCD0` → `#E0D9CC`   | `#3A322A` → `#2E2A25`                       |
| `accent`      | `#2D5FB8` 유지          | **`#85A9EC` 유지**(확정값)                  |

새 토큰.

- `margin`: 일기장 여백선. 라이트 `#8EA9DD`, 다크 `#4F6694`.
- `sheet` + `sheet-alpha`: 간지 바탕. 라이트 `251 250 246` / `.62`, 다크 `38 35 31` / `.74`.
- `flag-*`: 플래그 색 여섯(노랑 `242 201 76`, 분홍 `238 122 154`, 주황 `242 150 72`, 초록 `104 190 132`, 파랑 `92 140 232`, 보라 `156 128 214`). **강조색 규칙과 별개**이며 플래그에만 쓴다. 다크에서는 시안처럼 알파 .5 + 안쪽 테두리.

`card`·`card-raised`처럼 시안에 대응이 없는 토큰은 화면 이전이 끝난 뒤 쓰임을 확인해 정리한다(6절).

### 2.2 글자

서체는 그대로(마루 부리·Pretendard, 셀프호스팅). 크기를 시안으로 키운다. 기존 토큰 이름은 의미가 맞는 것에 새 값을 주고, 없는 것은 추가한다.

| 쓰임          | 시안            | 지금 대응                   |
| ------------- | --------------- | --------------------------- |
| 큰 제목       | 34/1.15 sans 700 | `page-title` 24              |
| 소제목        | 26/1.3 serif 700 | `section-title` 18           |
| 문장          | 25/1.6 serif 600 | `quote` 20                   |
| 큰 문장       | 30/1.55 serif 600 | 없음 → `quote-lg`           |
| 생각          | 19/1.65 serif 400 | `note` 15                   |
| 메타          | 15 sans 500     | `caption` 13                 |
| 라벨          | 14 sans 600     | `overline` 12                |

본문·버튼·입력 크기는 시안 각 화면의 값을 따라 토대 PR에서 표로 확정한다.

### 2.3 바탕과 간지

- **일기장 바탕:** 괘선과 파란 여백선이 화면 뒤에 고정된다(시안 `app.css` "일기장 괘선"). 찾기·알림·설정 같은 도구 화면은 여백선 없이 괘선만.
- **간지(벨럼):** 반투명 트레이싱지. 바탕 + 고운 결(grain) + 비스듬한 빛 + 얕은 그림자, 약한 `backdrop-filter`. 글라스모피즘(강한 블러)이 아니다. `prefers-reduced-transparency`에서는 불투명. **쌓여 있을 법한 것에만** 쓴다: 회상, 덧붙인 생각 묶음, 발췌집, 달마다 간지, 책 한 권의 기록 간지, 바텀 시트, 탭 바·상단 바의 스크롤 재질.
- 그림자 규칙: 일반 카드·도구는 그림자 없이 헤어라인. 깊이는 간지에만 허용한다. 프로필 3D 책·엽서의 그림자 예외는 사라진다.

### 2.4 간지 묶음 부품 `Pile`

시안 `pile.js`를 클라이언트 컴포넌트로 옮긴다. 값은 그대로다.

- 자리 `SLOT=[[0,0],[16,15],[32,30],[48,45]]`, 숨긴 장 `MID=[40,37]`, 깊이별 기울기 배율 `TILT=[.22,.7,.85,1]`, 숨긴 장 배율 `.9`.
- 보이는 자리 넷: 위 세 장 + 맨 아래 자리(가장 뒤의 장). 다섯 장 이상이면 사이 장은 숨긴다.
- 기울기는 종이마다 갖는다(1.3~3.2도, 바로 위 장과 반대 방향). 지터 ±4px. 뒤로 들어갈 때마다 새로 정한다.
- 넘김: WAAPI 한 애니메이션 560ms. 오른쪽으로 다음 장과 겹치지 않을 때까지(최소 48px는 화면에 남김) 빠졌다가 38% 지점(`translate(ox,-8px) rotate(3deg) scale(.985)`)에서 방향을 바꿔 맨 뒤 자리로. 나갈 때 `cubic-bezier(.33,1,.68,1)`, 돌아올 때 `cubic-bezier(.65,0,.35,1)`. 순서는 가장 멀리 빠진 순간에 바꾸고 나머지 장은 300ms로 한 칸씩 올라온다. 넘기는 중에는 새 넘김을 받지 않는다.
- 순서 바꾸기: React 상태로 순서를 바꾸면 그 순간 DOM이 재배치되어 CSS transition이 끊긴다. 시안처럼 넘기는 장은 WAAPI로 그리고(재배치에도 이어짐), 나머지 장은 상태 변경 후 transform transition으로 움직인다.
- 손으로 밀기: 가로 끌기만, 한계에 가까울수록 무거워짐(`lim·(1-e^(-dx/lim))`), 왼쪽은 최대 16px. 한계의 45% 이상 또는 속도 0.11px/ms 이상이면 넘김. 세로 움직임이 먼저면 스크롤에 양보. 끌어 넘긴 뒤 따라오는 클릭은 막는다.
- 동작 줄이기: 이동 없이 순서만 바꾸고 160ms 흐림.
- 접근성: 맨 위 장만 `aria-hidden=false`, "다음" 버튼과 위치 표시(`3/7`)를 함께 둔다.
- 넘기는 동안 가로 스크롤이 생기지 않게 `html, body { overflow-x: clip }`.

### 2.5 화면 틀

`AppShell`·`Navbar`를 교체한다(시안 `app.css` Apple식 바, `shell.js`).

- 모바일 상단 바: 큰 제목이 스크롤되어 사라지면 바에 작은 제목과 간지 재질이 나타난다. `IntersectionObserver`로 판단.
- 모바일 하단 탭 바: 떠 있는 캡슐, 안전 영역 반영. 지금의 `--app-*` 높이 변수 체계를 이어 쓴다.
- 데스크톱: Apple식 사이드바. 화면은 두 쪽 펼침. 데스크톱 홈은 한 화면 고정, 책장은 장 단위/버튼 전환.
- **장 넘김:** 모바일은 모든 화면이 한 화면씩 스냅된다(프로필 포함). 장 높이는 폭이 바뀔 때만 다시 잰다(주소창이 접히는 중 출렁임 방지). 규칙은 **덮이면 연결된 것, 넘어가면 다음 것**: 기본은 넘기기, 덮기는 앞 장에 얹히는 관계(덧붙인 생각)만. 소셜 피드는 글마다 가볍게 멈추는 연속 피드. 도구 화면은 스냅 없이 흐른다. 다음 장 머리 걸치기·처음 살짝 올라오기 같은 스크롤 안내는 넣지 않는다.
- 바텀 시트: 동작은 기존 Headless UI Dialog(포커스 관리·`InertBackground`) 그대로, 모양만 간지 재질. 데스크톱에서는 가운데 창.

### 2.6 움직임

곡선 토큰 `--ease-out`·`--ease-in-out`·`--ease-drawer`는 유지한다. 책장 3D 넘김 전용 `--ease-page`는 사라지는 화면과 함께 정리한다. 모든 움직임은 `prefers-reduced-motion`에서 이동을 빼고 흐림만 남긴다.

### 2.7 사라지는 것

프로필 3D 책, 소셜 엽서(절취선·그림자), 책장 3D 넘김, 카드 반복 위주의 홈. 책등 서가와 발췌집은 남는다(발췌집은 간지 묶음으로).

## 3. 화면 지도

주소는 1절의 새 주소를 쓴다. 화면 안쪽만 시안으로 바꾼다.

| 시안                      | 주소                                                       | 비고                                                                 |
| ------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------- |
| `home2` 오늘              | `/today`                                                   | 한 번에 한 장. 회상 간지는 쓰기 아래 겹침. 주간 장은 비어 보이지 않게 |
| `books`, `book-new`       | `/books`, `/books/new`                                     | 표지 없는 책만 책등 흉내(`shelf.js`)                                  |

## 4. 새 기능 (DB 스키마 변경 없음)

### 4.1 책 플래그

- 쪽 번호가 있는 기록마다 표지 오른쪽 옆면에서 플래그 하나가 기울기 없이 나온다. 책을 밀면 함께 움직인다.
- 세로 위치: `쪽 ÷ 전체 쪽수`. 전체 쪽수가 없으면 그 책에서 기록한 가장 큰 쪽을 끝으로 본다. 쪽 번호가 없는 기록은 플래그 없이 간지 쪽에만 있다.
- 색: 기록한 **날짜**(사용자 시간대) 순서대로 `flag-*` 여섯 색을 돌려 쓴다. 같은 날 = 같은 색. 사용자가 고르지 않는다.
- 누르면 그 기록으로. 누름 영역은 나온 부분만이며 옆 플래그와 겹치지 않는다. 몰린 플래그는 길이를 단계로 나눈다(시안에서 해결한 문제).
- 데이터: 이미 책 상세가 읽는 기록 목록에서 계산한다. 추가 조회 없음.

### 4.2 원고지 필사

- 새 주소 `/pilsa`. 오늘 화면의 쓰기 도구에서 들어간다.
- 한 칸에 한 글자, 띄어쓰기도 한 칸, 줄 첫 칸의 띄어쓰기는 쓰지 않는다. 모바일 칸 28px·8줄, 데스크톱 40px·6줄, 열 수는 폭에 맞춰 8~20.
- 빈 원고지 / 남긴 문장 따라 쓰기. 따라 쓰기는 다른 글자를 강조색으로 표시한다. 커서 깜빡임 없음.
- "남기기"는 보통의 문장 기록(`quote`, 책·쪽 선택)으로 저장한다. 필사로 썼다는 표시는 저장하지 않는다. 저장은 기존 기록 생성 API를 쓴다.
- 따라 쓸 문장 고르기는 기존 선택 UX 규칙(현재 선택 먼저, 검색·페이지네이션)을 따른다.

### 4.3 달마다 간지

- 나 화면의 일기장 장. 한 달에 한 장, 맨 위가 이번 달. 밀거나 "다음 달"로 넘긴다(간지 묶음).
- 각 장의 문장 = **그달 문장 중 이어 남긴 생각이 가장 많은 것**, 동점이면 더 최근 것. 생각이 하나도 없는 달은 그달의 가장 최근 문장. 문장이 없는 달은 장을 만들지 않는다.
- 데이터: DB 집계 한 번(RPC 또는 집계 쿼리)으로 달별 대표 문장만 가져온다. 본인 기록만, RLS 그대로. 상한: 최근 24개월.

## 5. 배포 방식

- `main`은 머지 즉시 프로덕션 배포되므로, 새 디자인은 **`redesign` 작업 브랜치**에 PR로 쌓는다. 앱 안에 옛·새 화면 스위치는 두지 않는다.
- 확인은 Vercel이 만드는 `redesign` 브랜치 미리보기 주소에서 한다. 시작 전에 확인할 것: 미리보기 배포가 켜져 있는지, Preview 환경변수가 어느 Supabase를 가리키는지, Supabase Auth 리다이렉트 허용 목록에 미리보기 주소가 있는지.
- 그사이 `main`의 수정은 주기적으로 `redesign`에 병합한다.
- DB가 필요한 변경(달마다 간지 집계 함수 등)은 추가만 하는 마이그레이션으로 먼저 적용해도 옛 화면에 영향이 없다.
- 완성 후 `redesign` → `main` 한 번 머지.

## 6. 순서

1. 이 스펙과 PRODUCT.md·디자인 검사 hook(PR #134에서 옮김) → `main`.
2. 주소 정리(1절) → `main`.
3. 최신 `main`에서 `redesign` 생성, 미리보기 주소 점검.
4. 토대(→ `redesign`, 각각 PR):
   1. 색·글자·바탕 토큰 + DESIGN.md·`docs/ui-guidelines.md`·AGENTS.md Design Context·PRODUCT.md 갱신(문서·토큰·구현을 같은 변경에서)
   2. 간지 재질 + `Pile`
   3. 화면 틀(상단 바·탭 바·사이드바·장 넘김·바텀 시트)
5. 화면 이전: 오늘 → 책(책장·등록·한 권) → 기록·발췌집 → 나·설정 → 소셜 → 찾기·알림·인증·공유.
6. 새 기능: 책 플래그, 원고지 필사, 달마다 간지.
7. 랜딩.
8. 사용자 실사용 확인(미리보기 주소, iPhone 설치형 앱 포함).
9. `redesign` → `main` 머지. 쓰이지 않는 옛 부품·토큰(`card-raised`, `--ease-page`, 3D 책·엽서 등) 제거, PWA 캐시 갱신, 프로덕션 스모크(www.readiary.net), 실기기 확인.
