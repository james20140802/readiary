## 1. 목적과 문제의식

Readiary의 목적은 사람들이 독서 습관을 갖게 하고, 읽은 내용과 감상을 미래에
돌아볼 수 있게 돕는 것이다. 현재 구조는 이 목적과 어긋나 있다.

- 기록 1건에 시작 페이지·종료 페이지·줄거리 요약이 전부 필수다. 페이지 수를
  모르면 기록할 수 없고, 전자책·오디오북 독자는 사용이 불가능하다.
- 보상 체계(배지 20종)는 요구하는 행동 비용에 비해 유인이 약하다.
- 과거 기록을 다시 보여주는 장치가 없다. "미래에 돌아본다"는 본래 목적이
  제품에 구현되어 있지 않다.
- UI는 토스식 미니멀리즘으로, 제작자의 다른 프로젝트와 차별화되지 않는다.

## 2. 핵심 결정 (전부 사용자 확정)

1. **기록의 원자 단위는 "문장"** — 페이지·감상·별점은 전부 선택 사항.
2. **entries는 type enum이 아니라 nullable 필드 조합** — 한 행 = 한 번의 기록 순간.
3. **완독은 사용자 선언** — 진행률 90% 게이트 폐지.
4. **배지 제거, 회고 중심 보상으로 교체** — 회상 카드·발췌집·월말 회고.
5. **UI는 에디토리얼/종이 감성** — 2서체 체계(콘텐츠 부리 + UI 산세리프),
   그림자 대신 헤어라인. 기울어진 도장 박스(스탬프)는 쓰지 않되 한자 장식은 허용.
6. **강조색은 2후보** — 파란 잉크 `#2D5FB8` vs 주홍 `#C1441E`. 구현 단계에서
   실화면 비교 후 확정. 기존 `#3B82F6` 원색은 쓰지 않는다.
7. **소셜 유지 + 외부 공유 강화** — 문장 카드 이미지 공유, 동적 OG.
8. **전면 개편 한 번에** — 기존 데이터는 무손실 마이그레이션.

## 3. 데이터 모델

### 3.1 entries 변경

```sql
-- 변경 후 개념 스키마
entries (
  id            uuid PK,
  user_book_id  uuid FK,
  date          date,          -- 사용자가 선택 가능(기본 오늘, 과거 백필 허용)
  quote         text NULL,     -- 책에서 옮겨 적은 문장
  note          text NULL,     -- 내 생각(한 줄 메모든 긴 감상이든)
  from_page     int  NULL,     -- 선택 사항으로 강등
  to_page       int  NULL,
  is_private    boolean DEFAULT false,
  created_at    timestamptz,
  CHECK (quote IS NOT NULL OR note IS NOT NULL)
)
```

- 채워진 필드가 기록의 성격을 정한다: quote만(필사) / note만(생각·감상) /
  quote+note(문장에 대한 생각). 길이는 표시 방식의 문제일 뿐 별도 타입이 없다.
- 저장 직후의 "확장"(생각 덧붙이기, 페이지 남기기)은 같은 행의 UPDATE다.
  행 분리·연결 없음. 기록 상세의 수정과 같은 경로.

### 3.2 user_books 변경

- `is_finished`는 진행률과 무관하게 사용자 선언으로만 설정한다.
- `progress`/`last_read_page`는 페이지를 입력한 기록이 있을 때만 계산되는
  부가 정보다. `update_user_book_progress` RPC는 페이지가 있는 기록만 반영하도록
  수정한다.

### 3.3 books 변경

- `total_pages`를 nullable로 변경. 책 등록 시 페이지 수 입력 강제를 제거한다
  (카카오 스크래핑 실패 시 수동 입력 요구하던 플로우 삭제).

### 3.4 신규: notifications

```sql
notifications (
  id         uuid PK,
  user_id    uuid,           -- 수신자
  actor_id   uuid,           -- 행위자
  type       text,           -- 'friend_request' | 'friend_accept' | 'like' | 'comment'
  entry_id   uuid NULL,
  read_at    timestamptz NULL,
  created_at timestamptz
)
```

### 3.5 제거

- `badges`, `user_badges` 테이블과 관련 코드 전부
  (`utils/badges.ts`, `utils/badgeConditions.ts`, `hooks/useBadgeAwarder.ts`,
  `lib/badges/condition.ts`(데드), 프로필 배지 그리드).

### 3.6 마이그레이션 순서

1. `entries`에 `quote` 컬럼 추가, `summary` → `note` 이름 변경,
   `from_page`/`to_page` nullable화, CHECK 제약 추가.
   기존 행은 자동으로 note-only 기록이 된다(무손실).
2. `books.total_pages` nullable화.
3. `notifications` 생성 + RLS.
4. `badges`/`user_badges`는 코드 제거 후 마지막에 drop
   (되돌릴 수 없으므로 배포 안정화 후).

## 4. 기록 플로우

1. 홈("오늘" 탭) 최상단에 입력창: "오늘 마음에 남은 문장을 남겨보세요".
   최근 읽던 책이 칩으로 미리 선택. 탭 한 번으로 다른 책 선택/새 책 등록.
2. 문장 입력 → 저장(INSERT). 여기서 기록은 완결.
3. 저장 완료 화면에 "생각 덧붙이기 · 페이지 남기기" 선택 버튼 → 같은 행 UPDATE.
   무시하고 떠나도 됨.
4. `date`는 기본 오늘, 과거 날짜 백필 허용(신규/수정 폼 비대칭 제거).
5. 긴 감상을 쓰고 싶으면 note에 길게 쓰면 된다 — 별도 "감상문" 개념 없음.

## 5. 화면 구조

내비게이션 4탭 유지, 역할 재정의:

| 탭 | 역할 |
|---|---|
| 홈("오늘") | 입력창 → 회상 카드 → 주간 리듬 → 읽고 있는 책. 피드 프리뷰 제거 |
| 내 책장 | 유지. 정렬/필터 단순화. 그리드에 책등(spine) 뷰 — 두께는 페이지 수 비례 |
| 소셜 | 피드 + 친구 관리로 일원화(중복 페이지 제거) |
| 프로필 | 배지 그리드 자리에 회고(발췌집 목록·월별 요약)가 들어옴 |

### 회고 기능 3종 (전부 파생 뷰 — 새 테이블 불필요)

- **회상 카드**: 같은 월-일의 과거 기록 우선, 없으면 무작위 과거 기록.
  기록이 적은 신규 사용자에게는 숨김.
- **발췌집**: 완독 선언 시 그 책의 기록(quote 우선)을 시간순으로 엮은
  책 상세의 특별 뷰. 표지(제목·저자·완독일·문장 수) + 리더 뷰.
- **월말 회고**: 매월 1일 홈 상단에 지난달 요약 카드.

### 스트릭 순화

- "연속 N일" 강조 대신 "이번 주 문장 N개" 누적 표현. 주간 도트 유지.
- 스트릭 계산은 KST 기준으로 수정(현재 UTC 판정 버그).

## 6. 디자인 시스템 (시안: "먹과 종이")

- **타이포**: 콘텐츠(문장·감상·책 제목)는 부리 서체(후보: 마루 부리, 리디바탕 —
  셀프호스팅), UI 크롬은 Pretendard 유지.
- **컬러 토큰**: 종이 `#F7F3EC` / 카드 `#FDFBF7` / 먹 `#221E1A` / 회갈 `#6E665C`
  / 헤어라인 `#E3DCD0` / 강조색은 2후보(§2-6). 다크는 어두운 종이
  (`#1B1612` 바탕, `#EAE2D6` 글).
- **표면**: 그림자 3단계 폐지 → 1px 헤어라인 보더.
- **날짜 표식**: 잉크색 작은 산세리프 라벨(레터스페이싱). 도장 박스 금지.
- 이모지 남용 제거, 아이콘은 lucide 단일화(react-icons 제거).
- 다크모드는 OS 설정 따름 유지(`darkMode: 'media'`), 앱 내 토글 없음.
- 미정의 토큰(`bg-background`, `text-secondary` 등)과 하드코딩 색상은
  토큰 교체 과정에서 전부 정리. 랜딩 페이지는 새 시스템으로 재작성.

## 7. 소셜과 공유

- 피드 렌더링을 소셜 탭 하나로 일원화. `DetailSocialFeedItem` 중복 두 벌 제거.
  피드 아이템은 새 문장 카드 컴포넌트 재사용.
- 좋아요는 `/api/likes` 경유로 통일(클라이언트 직접 조작 경로 제거).
- 친구 찾기: 닉네임#태그 정확 검색 유지 + 내 프로필 공유 링크(수신자는
  로그인 후 바로 친구 신청 화면).
- **문장 카드 이미지 공유**: 카드 DOM → 이미지(4:5), Web Share API 연동,
  하단에 작은 워드마크. `is_private` 기록은 공유 UI 숨김.
- **동적 OG**: `next/og`로 공개 기록의 문장 카드 조판 그대로 렌더.

## 8. 알림

- 인앱: `notifications` 테이블 + 탭바 뱃지 + 알림 목록. 발생 지점은
  친구 요청/수락, 좋아요, 댓글 API 핸들러.
- Web Push 리마인더("자기 전 한 문장"): opt-in, 시간 선택. 구현 순서상 마지막.

## 9. 함께 정리하는 기술 부채

- 스트릭 UTC→KST 수정, 페이지 통계 ±1 불일치 통일(기록당 `to - from + 1`).
- 데드 코드 제거: `StatsSection`, `TodaySummarySection`, `ProfileBadges`,
  `lib/badges/condition.ts`, 중복 `DetailSocialFeedItem/List`.
- 서버 컴포넌트에서 sonner 호출하는 버그(`books/[book_id]/page.tsx`) 제거.
- 이미지 최적화(1.3MB 기본 커버/1.5MB 배지 이미지), manifest themeColor 불일치
  수정, maskable 아이콘 추가.
- `ts-prune`/`unimported`를 devDependencies로 이동.

## 10. 범위 제외 (이번 개편에서 하지 않음)

- 앱 내 다크모드 토글, 장르/태그 시스템, 책 추천, 랭킹/리더보드,
  스트릭 프리즈 같은 추가 게이미피케이션.

## 11. 구현 순서(개요)

1. DB 마이그레이션(§3) → 2. 디자인 토큰·컴포넌트 시스템 → 3. 기록 플로우 →
4. 홈·회상 카드 → 5. 발췌집·프로필 → 6. 소셜 정리·공유 카드·OG →
7. 인앱 알림 → 8. 랜딩·기술부채 마무리 → 9. Web Push.

상세 태스크는 Notion 이슈 DB에 등록되어 있다(P0 3건, P1 5건, P2 6건, P3 1건).

## 12. 검증

- 마이그레이션: 기존 entries 전수에 대해 note = 구 summary, quote IS NULL 확인.
- 기록 플로우: 문장만 입력(2탭) / 확장 UPDATE / 과거 날짜 백필 / 비공개 토글.
- 회고: 회상 카드 쿼리(같은 월-일 우선), 발췌집(완독 선언 직후 생성),
  KST 경계(자정 전후) 스트릭 판정.
- 공유: OG 이미지가 비공개 기록에 대해 404, 공개 기록에 대해 문장 카드 렌더.
