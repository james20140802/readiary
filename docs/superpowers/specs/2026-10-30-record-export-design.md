# 내 기록을 텍스트로 꺼내기 — 설계

2026-10-30 · 브레인스토밍 결과. 표시가 없는 결정은 사용자가 정했고, *(설계자 판단)* 표시는 대화 중 제안해 사용자가 반대하지 않은 판단이다.

## 왜

독자는 자신이 남긴 문장과 생각을 AI(ChatGPT·Claude 등)에 붙여 넣고 **그 기록을 두고 함께 토의하고 싶다.** 노션·옵시디언으로 옮기거나 보관하는 것은 같은 텍스트로 따라오는 부수 용도다. Readiary의 "다시 만나는 기록" 철학을 앱 밖으로 넓히는 기능이며, 앱이 사라져도 기록이 내 손에 남는다는 안심도 준다.

## 목표

- 책 한 권 또는 한 달의 내 기록을 **마크다운 텍스트**로 꺼낸다.
- 붙여 넣는 즉시 AI가 "책의 문장"과 "나의 생각"을 구분하고 시간 흐름을 읽을 수 있는 모양이다.
- 휴대폰에서는 공유, 컴퓨터에서는 복사·파일 저장이 한두 번의 탭으로 끝난다.

## 비목표

- **전체 서재 한 번에 꺼내기.** 너무 크다는 판단으로 제외.
- **월별 일기장 화면.** 한 달을 한 권으로 엮는 화면은 별도 프로젝트로 이슈만 남긴다. 이번 꺼내기 로직은 나중에 그 화면에 그대로 붙일 수 있게 만든다.
- **AI에게 건네는 안내문**("아래는 내 기록이야, 같이 이야기하자"). 다른 곳에 쓸 때 애매해지므로 넣지 않는다. 기록만 담는다.
- CSV·JSON 등 기계용 형식, 친구 기록 꺼내기, 외부 공유 링크.

## 반목표 (기술적으로 돼도 실패인 것)

- 꾸밈(이모지·장식·앱 UI 문구)이 섞여 매번 지워야 하는 텍스트.
- 책의 문장과 내 생각이 구분되지 않는 텍스트.
- 닫힌 시트를 위해 전체 기록을 미리 가져오는 구현(AGENTS.md 데이터 접근 규칙).

## 꺼내는 범위와 입구

| 범위    | 입구                                                                                                                                                                       | 비고                                                                                                       |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 책 한 권 | 책 상세 `app/(app)/books/[book_id]/(detail)`                                                                                                                              | 읽는 중·완독 모두. 발췌집(`excerpts`)은 완독한 책만 열리므로(`isFinished` 아니면 책 상세로 redirect) 입구로 쓰지 않는다. |
| 한 달   | 책장 `app/(app)/books/(shelf)`                                                                                                                                             | 시트 안에서 달을 고른다. 월별 일기장이 생기면 같은 꺼내기를 거기에도 붙이고, 책장 입구를 남길지 그때 정한다. |

## 텍스트 모양

### 책 한 권

```markdown
# 아무튼, 메모

정혜윤 · 2026년 9월 3일 ~ 10월 21일 · 완독

## 2026년 9월 3일 · 24쪽

> 메모는 나를 위해 남겨 두는 작은 신호다.

이 문장을 읽고 내 노트 앱을 다시 열어 봤다. 쌓아 두기만 했던 것 같다.

- 2026년 10월 2일 덧붙임: 요즘은 일주일에 한 번 다시 읽는다.

## 2026년 9월 10일

나는 왜 밑줄을 긋고도 금방 잊어버릴까.
```

### 한 달

```markdown
# 2026년 10월의 기록

## 아무튼, 메모 — 정혜윤

### 10월 2일 · 112쪽

> …

…

## 작별하지 않는다 — 한강

### 10월 15일

…
```

### 규칙

- 책의 문장(`quote`)은 인용 `>`, 나의 생각(`note`)은 일반 문단. 둘 다 있으면 문장 → 생각 순.
- **기록 하나 = 제목 하나.** 같은 날 기록이 여러 건이면 날짜 제목을 기록마다 반복하고, 쪽수도 각 기록의 제목에 붙인다(`## 2026년 9월 3일 · 24쪽`, `## 2026년 9월 3일 · 31쪽`). 한 제목 아래 여러 기록을 묶지 않는다. 같은 날 안에서는 작성 시각 오름차순. *(설계자 판단: 책 상세 화면은 최신순이지만, 꺼낸 텍스트는 읽은 흐름대로 읽혀야 한다)*
- 덧붙인 생각(`entry_reflections`)은 원래 기록 아래에 날짜를 달아 이어 붙인다. 본문이 여러 줄이면 이어지는 줄을 공백 2칸 들여 써서 같은 목록 항목 안에 둔다. 빈 줄은 들여 쓴 빈 줄로 보존한다. *(설계자 판단)* **원래 기록을 따라간다**: 9월 기록에 10월에 덧붙인 생각은 9월 기록과 함께 나오고, 10월 텍스트에는 나오지 않는다.
- 쪽수·저자·덧붙임·완독 표시는 값이 있을 때만 쓴다. 빈 칸 표기를 남기지 않는다.
- 쪽수는 `from_page`/`to_page`로 `24쪽` 또는 `24~31쪽`. *(설계자 판단)*
- 정렬은 시간순. 책 한 권은 기록 날짜 → 작성 시각, 덧붙임은 작성 시각순. 한 달은 **책별로 묶고**, 책 안에서 날짜순, 책 묶음 순서는 그달 첫 기록 날짜순. 묶음 단위는 `user_book_id`다(같은 책을 다시 등록해 읽었다면 별도 묶음). 책 한 권 입구와 같은 단위다. *(설계자 판단)*
- 책 머리말의 기간은 첫 기록일 ~ 마지막 기록일. 완독이면 `· 완독`. *(설계자 판단)*
- 공개/비공개 여부는 텍스트에 표시하지 않는다. 비공개 기록·비공개 덧붙임도 포함한다(내 기록을 내가 꺼내는 것). *(설계자 판단)*
- 사용자가 쓴 줄바꿈은 보존한다. 여러 줄 문장은 줄마다 `>`를 붙인다. 사용자 텍스트 안의 마크다운 기호는 이스케이프하지 않는다. *(설계자 판단: 붙여 넣기 목적에서는 원문 보존이 낫다)*
- 날짜는 KST 기준 한국어 표기(`2026년 9월 3일`, 한 달 텍스트 안에서는 `10월 2일`).

## 시트와 동작

- 입구에서 "기록 꺼내기" 버튼 → 공용 `Sheet`(바텀시트) 열림.
- 시트 안: (한 달이면 맨 위에 달 선택) → 꺼낼 텍스트 **미리보기** → 버튼.
- 버튼은 기기에 따라 다르다.
  - 휴대폰·태블릿(`navigator.share` 지원 + `(pointer: coarse)`): **공유하기** · **복사하기**
  - 그 밖(컴퓨터): **복사하기** · **파일로 저장**(`.md`)
  - 맥 Safari처럼 컴퓨터에서 공유를 지원해도 숨긴다. 휴대폰의 파일 저장은 공유 시트의 "파일에 저장"으로 대신한다. *(설계자 판단)*
- 복사 성공은 짧은 토스트(`sonner`)로 "복사했어요". 실패하면 미리보기의 텍스트를 직접 선택할 수 있다는 안내를 보여 준다. 공유를 사용자가 취소하면 아무것도 표시하지 않는다.
- 시트 안에 "비공개 기록도 포함돼요"를 작게 알린다.
- 파일 이름: `readiary-<책 제목>.md`, `readiary-2026-10.md`. 파일 이름에 쓸 수 없는 문자는 바꾼다.
- 문구는 행동과 결과로 쓴다("기록 꺼내기", "복사하기", "공유하기", "파일로 저장").

### 한 달 선택

- 기록이 있는 달만 고를 수 있다. 처음에는 가장 최근 달이 선택돼 있다.
- 달 후보 목록과 선택한 달의 기록은 따로 불러오고, 로딩·실패·재시도도 따로 처리한다(AGENTS.md 선택 UX 규칙).
- 기록이 없는 상태에서는 입구 버튼을 숨기거나 비활성화한다(빌더가 기존 빈 상태 문법에 맞춰 정한다).

## 데이터

- **시트가 열릴 때** 필요한 범위만 가져온다. 닫힌 시트를 위해 미리 가져오지 않는다.
- 책 한 권: 그 `user_book`의 기록 전부와 그 기록들의 덧붙인 생각 전부. 책 상세는 이미 기록을 갖고 있지만, 덧붙인 생각은 화면에서 페이지 단위(`REFLECTION_PAGE_SIZE`)로만 불러오므로 꺼내기용으로 한 번에 가져오는 경로가 필요하다.
- 한 달: 로그인 사용자의 그달 `entries.date` 범위 기록 + 책 정보 + 그 기록들의 덧붙인 생각. 기존 `get_monthly_recap`은 집계만 돌려주므로 재사용할 수 없다.
- 기록이 있는 달 목록은 집계(달별 존재 여부)로 가져온다.
- 구현 방식(security invoker RPC 하나로 묶을지, 기존 서버 쿼리를 쓸지)은 빌더가 정한다. 다만 RLS·인증 확인을 우회하지 않고, 새 RPC라면 `20261030090000_explicit_table_api_grants.sql`·`docs/operations/supabase-api-grants.md` 규칙대로 `revoke … from public, anon` + `grant execute … to authenticated`를 명시한다. 응답은 본인 기록으로 한정한다.
- 크기 상한: 꺼내는 범위가 이미 책 한 권·한 달로 작다. 별도 상한은 두지 않는다. 다만 비정상적으로 큰 경우(예: 한 달 1,000건 이상)의 처리는 빌더가 판단해 기록한다. *(설계자 판단)*

## 마크다운 생성

- 데이터 → 텍스트 변환은 UI와 분리된 순수 함수 한 곳(`lib/` 아래)에 둔다. 책 한 권·한 달 두 진입 함수가 같은 기록 서식 함수를 공유한다. 월별 일기장이 나중에 이 함수를 그대로 쓴다.
- 위 규칙 전부(인용·생략·정렬·덧붙임 귀속·줄바꿈·날짜)를 단위 테스트로 고정한다.

## 디자인

- 시트·버튼·토스트는 기존 공용 컴포넌트와 토큰을 쓴다(`Sheet`, `Button` 주요=먹/보조=헤어라인). 미리보기는 종이 바탕에 헤어라인, 그림자 없음. 미리보기 텍스트는 마크다운 원문을 그대로 보여 준다(사용자가 실제로 받는 것). 글꼴은 빌더 판단이나 원문 확인이 목적이므로 산세리프 또는 고정폭이 자연스럽다.
- 입구 버튼은 각 화면의 보조 행동 자리에 둔다. 주인공(문장)보다 눈에 띄지 않게 한다.

## 검증

- 단위 테스트: 마크다운 생성 규칙 전부, 기기별 버튼 분기 판정.
- 화면: 모바일 폭, 라이트·다크, 키보드(시트 열기·버튼·닫기), 로딩·빈 상태·오류·성공.
- 실기기: iOS 설치형 PWA와 일반 Safari를 나눠 공유 시트로 ChatGPT·Claude 앱에 긴 텍스트(한 달 분량)가 잘리지 않고 넘어가는지, 클립보드 복사가 되는지. 확인하지 못한 조건은 PR에 미검증으로 적는다.

## 빌더에게 맡기는 것

- 입구 버튼의 정확한 위치·아이콘, 시트 안 배치와 미리보기 높이.
- 데이터 가져오기 방식(RPC vs 서버 쿼리)과 API 경로.
- 달 선택 UI의 형태(칩·목록·셀렉트), 빈 상태 처리.
- 큰 데이터 처리, 파일 이름 정리 규칙의 세부.

## 후속 이슈
