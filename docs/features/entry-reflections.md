# 지난 기록에 지금의 생각 이어 남기기

원래 문장·생각은 그대로 두고, 같은 기록 아래에 날짜별 생각을 남긴다. 생각만 있는 원문에도 사용할 수 있다. 원문의 날짜·쪽수·책 진도·기록 수·피드 정렬·회고 집계는 바뀌지 않는다.

## 화면과 행동

- 엔트리 상세: 출처와 원래 날짜 → 문장 → 남긴 생각 → 원문의 좋아요·공유·수정 → 오래된 순의 이어 남긴 생각 → 댓글. 날짜·쪽수·비공개 표시는 원문 위에 한 번만 둔다. 원문 수정과 생각 남기기는 별개 행동이다.
- 책 상세: 원고 흐름을 유지하면서 최근 생각의 날짜와 두 줄 요약, 개수를 보여 준다. 생각 보기와 작성 링크를 누르면 엔트리 상세로 이동한다.
- 친구 엽서: 앞면과 뒤집기를 유지한다. 뒷면에 열람 가능한 최근 생각과 개수를 보여 주고 해당 엔트리 상세로 이동한다. 엽서 너비 560px 미만에서는 날짜·생각 미리보기를 숨기고 생각 보기 링크만 남긴다. 좁은 화면에서는 표지를 책 정보 옆에 붙여 높이를 줄인다.
- 홈 최근 문장·다시 꺼낸 문장·월별 회고: 문장 자체는 공통 읽기 모달로 연다. 모달 오른쪽 아래에는 파란색 ‘자세히 →’ 링크를 둔다. 모달의 ‘이어 남긴 생각 보기’와 ‘지금의 생각 남기기’는 엔트리 상세로 이동한다. 회상 카드의 작성 버튼은 제목·지은이 줄 오른쪽에 놓고 공간이 부족하면 다음 줄 오른쪽으로 내린다. 작성 링크는 상세에서 작성란을 바로 열고 입력창으로 초점을 옮긴다. 상세 작성 버튼도 오른쪽 아래에 놓는다.
- 작성 폼: 괘선형 입력과 기존 `비공개` 토글 버튼을 사용하며 기본은 비공개다. 원문이 공개된 경우에만 비공개를 해제해 친구에게 공개할 수 있다. 작성·수정 폼의 닫기 행동은 ‘취소’이며 보관 가능한 초안은 유지한다. 새 생각은 최대 10,000 유니코드 문자다.
- 수정: 작성일·순서를 유지한다. `updated_at` 버전이 다르면 현재 저장된 내용을 보여 주고, 쓰던 내용은 유지한 채 새 버전을 기준으로 다시 저장하게 한다.
- 삭제: 개별 생각만 삭제할 수 있다. 원문 삭제 전에는 함께 지워질 생각 수를 새로 확인한다. 원문과 책 삭제는 FK cascade로 연결된 생각도 지운다.

## 권한과 공개 범위

`entry_reflections`의 SELECT/INSERT/UPDATE/DELETE는 인증 사용자와 RLS로 제한한다. 원문 소유자만 쓰고 고칠 수 있다. 친구 열람에는 현재 accepted 관계, 공개 원문, 공개 생각이 모두 필요하다. 비공개 생각의 존재는 친구용 개수·최근 요약에도 포함되지 않는다.

원문을 비공개로 바꾸면 연결된 모든 생각이 친구에게 숨겨진다. 다시 공개할 때는 기존에 친구 공개로 지정한 생각도 다시 보인다는 확인을 받는다. 원문 공개 범위 변경만으로 개별 선택을 바꾸지는 않는다. 단, 비공개 원문 아래에서 생각을 수정하면 API와 DB가 해당 생각을 비공개로 저장한다. 오래 열린 편집창에도 동일하게 적용한다.

외부 공유 링크, OG/카드 이미지, 완독 발췌집에는 이어 남긴 생각을 넣지 않는다. 익명 역할에는 테이블 조회와 요약 RPC 실행 권한이 없다. 새 알림이나 친구 피드 재노출을 만들지 않는다. 공유 API·이미지 쿼리·발췌집은 기존 원문 필드만 사용한다.

## 데이터와 캐시

마이그레이션: `supabase/migrations/20260923082615_entry_reflections.sql`.

- `get_entry_reflection_summaries(uuid[])`: 호출당 최대 100개 원문, RLS를 거친 개수와 최근 240자. 목록 서버 로딩과 다시 포커스할 때의 배치 갱신에 사용한다. 닫힌 패널의 전체 생각을 미리 읽지 않는다.
- `GET /api/entries/:id/reflections`: 20개씩 `(created_at,id)` 커서 페이지네이션. 전체 원문과 별도 요청이다.
- `POST`: 브라우저가 만든 UUID를 재사용한다. 재전송은 기존 생각을 반환하며 수정된 내용을 덮어쓰지 않는다.
- `PATCH /:reflection_id`: `updated_at` 조건부 수정. 동일한 결과의 재시도는 성공으로 확인한다. `DELETE`는 동일 원문·생각 ID에 한정한다.
- 읽기·쓰기 응답은 `private, no-store`와 `Vary: Cookie`. 기존 PWA NetworkOnly 규칙이 `/api/`와 Supabase 응답을 포함한다.
- 목록 요약은 메모리에만 유지하고 포커스 복귀, 공개 범위에 영향을 받는 재로딩, 생각 변경 시 재확인한다. 계정 변경·로그아웃 시 표시와 초안을 비운다.

## 초안과 실패

초안은 현재 탭의 `sessionStorage`에 사용자·원문·수정 대상별로 보관한다. 수정 초안은 시작한 `updated_at`도 보관한다. 저장 결과가 불명확하면 생성 요청 UUID와 본문을 유지하며 `저장 확인·재시도`로 같은 요청을 보낸다. 초안 보관 실패를 명시하고, 접기·닫기 전에 버리기 확인을 받는다.

일시적 재조회 실패는 작성 중인 폼을 언마운트하지 않는다. 추가 페이지에서 고치던 생각도 첫 페이지 재조회 때문에 사라지지 않는다. 명시적인 접근 해제(401/403/404)나 계정 변경에는 개인 기록 표시를 비운다. 사용자가 로그아웃하거나 다른 계정으로 전환하면 해당 계정의 초안도 정리한다.

## 배포와 검증 경계

앱 배포 전에 이 additive 마이그레이션을 적용하고 테이블/RLS/RPC 권한을 읽어 확인해야 한다. 운영 DB 적용은 별도 승인이 필요한 운영 작업이다. 2026-09-23 사용자 승인 후 운영 DB에 두 마이그레이션을 적용했다. 마이그레이션 없이 앱을 먼저 배포하면 생각 조회·작성과 원문 삭제 전 개수 확인이 실패한다.

검증은 다음을 구분한다.

- 실제 migration SQL을 PGlite의 PostgreSQL에서 실행: 소유자·친구·제삼자·익명 접근, 개별 공개, 원문 공개 변경, 관계 변경, 불변 열 권한, 길이·중복·버전 충돌, cascade.
- Vitest API 계약: idempotent 재시도, 커서/페이지 크기, 수정 충돌, 오류에서 SQL 세부정보 미노출.
- jsdom 컴포넌트: 저장 공간 실패 + 포커스 재조회 실패, 첫 페이지 밖 수정의 유지, 계속 쓰기·버리고 접기 분기, 접근 해제 시 폼 제거.
- CUA 실제 브라우저의 합성 fixture: production 컴포넌트·토큰·서체를 사용하되 auth/router/fetch를 로컬 대체했다. 390px/1280px, 라이트/다크 토큰, 작성·접기·초안 복원·저장, 포커스 순환/Escape/복원, 친구 작성 도구 숨김을 확인했다. 운영 계정 쓰기 검증이나 OS 테마 변경 증거로 해석하지 않는다.
- 별도 필요: 운영 마이그레이션 이후 실제 로그인 계정의 end-to-end, iOS 설치형 PWA, VoiceOver/실제 가상 키보드.

전체 제품의 기존 스타일 드리프트는 이번 기능에서 일괄 수정하지 않는다. Frontend Design Premium 정적 감사는 변경하지 않은 기존 파일의 8개 지적(버튼 동작 검출, 기존 폼 검증 선언, 스크롤바)을 남겼다. 새 기능 범위에는 해당 지적이 없다.

## 단계적 공개

`20260923082632_entry_reflections_rollout.sql`을 기능 마이그레이션 다음에 적용한다. `feature_rollouts`의 `entry_reflections` 행은 기본적으로 꺼져 있다. 운영자가 `enabled=true`, `percentage=0`으로 두고 `user_ids`에 테스트 계정 UUID만 넣어 첫 공개를 시작한다. 이메일과 대상 목록은 브라우저에 전달하지 않는다.

- `enabled=false`: 전체 중지. 기존 생각 데이터는 보존한다.
- `enabled=true`, `percentage=0`: 허용 목록의 계정만 사용한다.
- `percentage=10`, `50`, `100`: 사용자 UUID를 기능별로 해시한 고정 집단에 순차 공개한다. 비율을 늘려도 이전 대상은 유지되며, 소규모 사용자 수에서 실제 인원 비율이 정확히 일치하지는 않는다.
- `entry_reflections_enabled()`는 인증된 호출자 자신의 결과만 반환한다. 설정 테이블은 클라이언트 조회·수정을 금지하고 RLS를 켠다. 설정 누락·조회 실패·로그아웃은 비활성으로 처리한다.
- 보호된 화면에서 서버가 최초 값을 전달하고, 창 포커스·계정 전환 시 갱신한다. API는 매 요청마다 확인한다. 켜 둔 화면의 갱신 전에도 DB 쓰기는 즉시 차단된다.
- 비대상 계정에는 홈 작성 버튼, 책·엽서·읽기 모달의 생각 미리보기, 상세의 생각 영역을 숨긴다. 기존 문장 읽기·좋아요·댓글은 유지한다. 이전 앱 전체를 제공하는 버전 분할이 아니라, 새 앱에서 생각 기능을 선택적으로 여는 방식이다.
- 개별 생각 읽기·쓰기 API와 배치 요약은 비대상 계정에 404를 반환한다. 원문 소유자의 단일 요약은 기존 생각을 모르고 삭제하거나 재공개하지 않도록 개수만 계속 제공한다(본문 미제공). 0개 삭제 안내는 기존 기록 삭제 문구를 사용한다.
- DB에는 기존 소유권 RLS와 함께 INSERT/UPDATE/DELETE의 restrictive 플래그 정책을 추가한다. 이미 저장된 데이터의 SELECT는 기존 권한 범위에서 유지한다. 기능 플래그는 기존 친구·개인정보 권한을 대체하지 않는다.

운영 변경은 SQL Editor 등 운영자 경로에서 `update public.feature_rollouts set enabled = false where key = 'entry_reflections';`처럼 대상 행만 수정하고 설정 및 호출 결과를 읽어 확인한다. 비율 확대와 허용 계정 변경은 별도 운영 결정이며 이번 최초 배포는 테스트 계정 한 명에 한정한다. 앱 되돌리기는 이 두 additive 마이그레이션을 삭제하지 않은 채 진행한다.


### 최초 운영 적용 결과 (2026-09-23)

운영 프로젝트 `piqlggyuhhicnjywombg`에 `20260923082615_entry_reflections`, `20260923082632_entry_reflections_rollout`을 적용했다. MCP가 발급한 실제 migration history 버전으로 파일명과 테스트 참조를 맞춰 후속 CLI 배포가 중복 적용하지 않도록 했다. 기존 데이터 구조는 삭제·변경하지 않았다.

RLS 활성화, 기존 소유권 정책 4개와 추가 restrictive 쓰기 정책 3개, 익명 테이블/RPC 권한 없음, 설정 테이블의 클라이언트 조회·수정 권한 없음, 소유자 열 변경 권한 없음을 읽어 확인했다. 운영 DB에서 authenticated 역할과 트랜잭션 한정 사용자 claim으로 테스트 계정 `true`, 비대상 UUID `false`를 확인했다. 이는 실제 브라우저 로그인 E2E와 구분한다. 초기 설정은 전체 비율 0%, 허용 계정 1명이다.

Security Advisor의 신규 알림 두 건은 의도된 구성이다: `feature_rollouts`는 RLS 정책 없이 직접 접근을 전부 막고, 인증 사용자에게 허용한 `entry_reflections_enabled()`는 SECURITY DEFINER로 설정을 읽되 호출자의 boolean만 반환한다. 빈 search_path, 인자 없는 auth.uid() 평가, PUBLIC/anon 실행 권한 해제를 확인했다. 기존 프로젝트 알림은 이번 배포와 별도로 유지한다.

검증: 전체 453개 테스트 통과 후 안전 개수 조회 테스트를 추가했고, 관련 36개 테스트·TypeScript·변경 파일 ESLint·프로덕션 빌드가 통과했다. 합성 미리보기 393px에서 플래그 on/off 및 라이트·다크를 확인했다. 실기기 iOS PWA/VoiceOver는 미검증이다.


후속 리뷰 보완: `20260923084120_reflection_private_edits`를 운영에 적용하고 트리거 정의·실행 권한을 읽어 확인했다. 원문이 비공개면 기존 공개 생각도 수정 시 비공개로 저장한다. 재공개 확인란은 소유자 전용 `summary?publicOnly=1`로 확인한 공개 생각이 1개 이상일 때만 표시한다. 0개이면 추가 확인 없이 저장하며, 조회 실패는 재시도한다. 이 안전 확인은 플래그와 독립적이므로 한때 기능을 쓰다가 대상에서 빠진 계정도 보호한다. 관련 40개 테스트와 타입·린트 검사를 통과했다.
