# 지난 기록에 지금의 생각 이어 남기기

원래 문장·생각은 그대로 두고, 같은 기록 아래에 날짜별 생각을 남긴다. 생각만 있는 원문에도 사용할 수 있다. 원문의 날짜·쪽수·책 진도·기록 수·피드 정렬·회고 집계는 바뀌지 않는다.

## 화면과 행동

- 엔트리 상세: 출처와 원래 날짜 → 문장 → 그때 남긴 생각 → 오래된 순의 이어 남긴 생각 → 좋아요·댓글. 원문 수정과 생각 남기기는 별개 행동이다.
- 책 상세: 원고 흐름을 유지하면서 최근 생각의 날짜와 두 줄 요약, 개수를 보여 준다. 같은 자리에서 펼치고 접고 작성한다.
- 친구 엽서: 앞면과 뒤집기를 유지한다. 뒷면에 열람 가능한 최근 생각과 개수를 보여 주고 공통 읽기 패널로 연결한다.
- 홈 최근 문장·다시 꺼낸 문장·월별 회고: `EntryReader`를 함께 사용한다. 모바일은 하단 패널, 넓은 화면은 중앙 패널이다. 원문과 생각 로딩·실패·재시도를 분리하고, 전체 문장을 내부 스크롤로 읽는다.
- 작성 폼: 괘선형 입력, 기본 나만 보기. 원문이 공개된 경우에만 친구 공개를 선택할 수 있다. 새 생각은 최대 10,000 유니코드 문자다.
- 수정: 작성일·순서를 유지한다. `updated_at` 버전이 다르면 현재 저장된 내용을 보여 주고, 쓰던 내용은 유지한 채 새 버전을 기준으로 다시 저장하게 한다.
- 삭제: 개별 생각만 삭제할 수 있다. 원문 삭제 전에는 함께 지워질 생각 수를 새로 확인한다. 원문과 책 삭제는 FK cascade로 연결된 생각도 지운다.

## 권한과 공개 범위

`entry_reflections`의 SELECT/INSERT/UPDATE/DELETE는 인증 사용자와 RLS로 제한한다. 원문 소유자만 쓰고 고칠 수 있다. 친구 열람에는 현재 accepted 관계, 공개 원문, 공개 생각이 모두 필요하다. 비공개 생각의 존재는 친구용 개수·최근 요약에도 포함되지 않는다.

원문을 비공개로 바꾸면 연결된 모든 생각이 친구에게 숨겨진다. 다시 공개할 때는 기존에 친구 공개로 지정한 생각도 다시 보인다는 확인을 받는다. 기존의 개별 공개 선택을 임의로 바꾸지 않는다.

외부 공유 링크, OG/카드 이미지, 완독 발췌집에는 이어 남긴 생각을 넣지 않는다. 익명 역할에는 테이블 조회와 요약 RPC 실행 권한이 없다. 새 알림이나 친구 피드 재노출을 만들지 않는다. 공유 API·이미지 쿼리·발췌집은 기존 원문 필드만 사용한다.

## 데이터와 캐시

마이그레이션: `supabase/migrations/20260921065117_entry_reflections.sql`.

- `get_entry_reflection_summaries(uuid[])`: 호출당 최대 100개 원문, RLS를 거친 개수와 최근 240자. 목록 서버 로딩과 다시 포커스할 때의 배치 갱신에 사용한다. 닫힌 패널의 전체 생각을 미리 읽지 않는다.
- `GET /api/entries/:id/reflections`: 20개씩 `(created_at,id)` 커서 페이지네이션. 전체 원문과 별도 요청이다.
- `POST`: 브라우저가 만든 UUID를 재사용한다. 재전송은 기존 생각을 반환하며 수정된 내용을 덮어쓰지 않는다.
- `PATCH /:reflection_id`: `updated_at` 조건부 수정. 동일한 결과의 재시도는 성공으로 확인한다. `DELETE`는 동일 원문·생각 ID에 한정한다.
- 읽기·쓰기 응답은 `private, no-store`와 `Vary: Cookie`. 기존 PWA NetworkOnly 규칙이 `/api/`와 Supabase 응답을 포함한다.
- 목록 요약은 메모리에만 유지하고 포커스 복귀, 공개 범위에 영향을 받는 재로딩, 생각 변경 시 재확인한다. 계정 변경·로그아웃 시 표시와 초안을 비운다.

## 초안과 실패

초안은 현재 탭의 `sessionStorage`에 사용자·원문·수정 대상별로 보관한다. 수정 초안은 시작한 `updated_at`도 보관한다. 저장 결과가 불명확하면 생성 요청 UUID와 본문을 유지하며 `저장 확인·재시도`로 같은 요청을 보낸다. 초안 보관 실패를 명시하고, 접기·닫기 전에 버리기 확인을 받는다.

일시적 재조회 실패는 작성 중인 폼을 언마운트하지 않는다. 추가 페이지에서 고치던 생각도 첫 페이지 재조회 때문에 사라지지 않는다. 명시적인 접근 해제(401/403/404)나 계정 변경에는 개인 기록 표시를 비운다. 사용자가 로그아웃하거나 다른 계정으로 전환하면 해당 계정의 초안도 정리한다.

## 배포와 검증 경계

앱 배포 전에 이 additive 마이그레이션을 적용하고 테이블/RLS/RPC 권한을 읽어 확인해야 한다. 운영 DB 적용은 별도 승인이 필요한 운영 작업이다. 현재 구현 작업에서는 운영 마이그레이션을 실행하지 않았다. 마이그레이션 없이 앱을 먼저 배포하면 생각 조회·작성과 원문 삭제 전 개수 확인이 실패한다.

검증은 다음을 구분한다.

- 실제 migration SQL을 PGlite의 PostgreSQL에서 실행: 소유자·친구·제삼자·익명 접근, 개별 공개, 원문 공개 변경, 관계 변경, 불변 열 권한, 길이·중복·버전 충돌, cascade.
- Vitest API 계약: idempotent 재시도, 커서/페이지 크기, 수정 충돌, 오류에서 SQL 세부정보 미노출.
- jsdom 컴포넌트: 저장 공간 실패 + 포커스 재조회 실패, 첫 페이지 밖 수정의 유지, 계속 쓰기·버리고 접기 분기, 접근 해제 시 폼 제거.
- CUA 실제 브라우저의 합성 fixture: production 컴포넌트·토큰·서체를 사용하되 auth/router/fetch를 로컬 대체했다. 390px/1280px, 라이트/다크 토큰, 작성·접기·초안 복원·저장, 포커스 순환/Escape/복원, 친구 작성 도구 숨김을 확인했다. 운영 계정 쓰기 검증이나 OS 테마 변경 증거로 해석하지 않는다.
- 별도 필요: 운영 마이그레이션 이후 실제 로그인 계정의 end-to-end, iOS 설치형 PWA, VoiceOver/실제 가상 키보드.

전체 제품의 기존 스타일 드리프트는 이번 기능에서 일괄 수정하지 않는다. Frontend Design Premium 정적 감사는 변경하지 않은 기존 파일의 8개 지적(버튼 동작 검출, 기존 폼 검증 선언, 스크롤바)을 남겼다. 새 기능 범위에는 해당 지적이 없다.
